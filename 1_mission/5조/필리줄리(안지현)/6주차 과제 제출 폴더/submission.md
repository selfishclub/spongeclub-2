## 결과물

`6주차 과제 제출 폴더/gtm-tracker/` — 로컬에서 `npm install && npm run dev` 한 번이면 뜨는 Next.js 앱.
Julie OS 웨이트리스트 홍보를 채널·소재별로 추적하는 GTM 도구다.

| 화면 | 하는 일 |
|---|---|
| `/admin` | 채널 고르고 "만들기" → `/l/{code}` 단축 링크 생성, 클립보드 자동 복사, QR. 하단 "장부"에 링크별 클릭·신청·전환율 |
| `/l/[code]` | 클릭 기록(미리보기 봇 제외) 후 UTM 붙여서 `/waitlist`로 302 |
| `/waitlist` | Julie OS 신청 폼. 들어온 UTM을 그대로 신청 레코드에 저장 |
| `/dashboard` | 기간별(오늘/7일/30일/전체) 클릭·신청·전환율, 일별 추이 차트, 채널별·소재별 표 |

- DB는 파일 하나(SQLite). 계정도 배포도 필요 없음.
- 순수 로직(단축코드 생성, 봇 필터링, 대시보드 집계)에 단위 테스트 35개.
- 만든 링크 → 클릭 → 신청 → 장부·대시보드 반영까지 전 구간을 curl로 end-to-end 검증 완료.
- 설계·구현 계획 문서: `gtm-tracker/DESIGN.md`, `gtm-tracker/PLAN.md`

> 스크린샷은 `이미지첨부/`에 추가 예정 (직접 `npm run dev` 띄워서 4개 화면 캡처).

## 삽질 과정

### 1. "이거 봐봐, 너도 만들 수 있어? 만들어줘"에서 시작

클럽마스터가 올린 VETD 대시보드/링크빌더 스크린샷을 보고 시작했다. 먼저 범위부터 좁혔다 —
실배포(Vercel+Supabase) 대신 **로컬에서 바로 도는 데모**, 스타일도 Tailwind 없이 CSS 하나로.
페이지 수가 적은데 빌드 도구를 얹으면 설치가 꼬일 수 있어서다.

### 2. Node.js가 아예 안 깔려 있었다

`node --version`부터 실패. winget으로 Node 24 LTS 설치.

### 3. better-sqlite3가 컴파일에서 막혔다

`npm install`이 `better-sqlite3` v11을 소스에서 빌드하려다 실패 — Node 24용 프리빌트 바이너리가
없고, 이 컴퓨터엔 Python(node-gyp용)도 없었다. 최신 v13으로 올리니 Node 24 프리빌트 바이너리가
바로 붙었다. 계획 문서에 버전을 못박고 진행.

### 4. 13개 태스크로 쪼개서 하나씩 TDD로

스캐폴딩 → DB 스키마 → 순수 헬퍼(단축코드·봇 필터) → 링크/클릭/장부 → 대시보드 집계 →
API 라우트 → 리다이렉트 → QR → 관리자 화면 → 신청 폼 → 대시보드 화면 → README·검증.
각 태스크마다 실패 테스트 먼저 쓰고, 구현하고, 리뷰를 붙였다.

### 5. 리뷰가 잡아낸 것들 — 특히 "숫자가 미묘하게 틀리는" 버그

태스크별 리뷰에서: 잘못된 요청 본문에 500 대신 400 반환, fetch 실패 시 화면이 흰 화면으로
깨지는 것 등을 고쳤다. 그리고 마지막 전체 리뷰에서 **채점 대상인 대시보드 숫자가 조용히
틀리는** 4가지가 나왔다:

- **인스타 프로필 링크의 소재 코드가 전부 빈 값** → 프로필 링크를 2개 만들면 둘 다 같은 신청을
  중복 집계. (소재 코드에 `bio01`, `bio02`… 번호를 붙이고, 같은 채널 내 중복 코드를 막아서 해결)
- **"소재 상위 10" 표만 기간 필터를 무시** → 타일은 "오늘"인데 표는 전체 기간을 보여줌.
- **봇 차단 정규식의 `kakaotalk`이 카카오톡 인앱 브라우저까지 걸러냄** → 카카오 채널의 실제
  클릭이 0으로 찍힘. (미리보기 스크래퍼 UA `kakaotalk-scrap`만 막도록 좁힘)
- **대시보드 날짜 경계가 UTC** → 한국시간 오전 9시 전에는 "오늘"이 하루 어긋남. 쿼리와 화면
  양쪽 다 로컬 시간 기준으로 고침.

### 6. 공유 저장소에서 다른 조원 파일을 커밋할 뻔함

작업 중 스테이징에 다른 조원의 미추적 파일(`아람/자기소개.md`)이 섞여 커밋된 걸 발견,
커밋을 되돌리고 로컬 제외 처리. 이후엔 파일을 경로로만 명시해서 스테이징.

## 인사이트

> **GTM 트래킹 도구는 "만드는 것"보다 "숫자가 맞는지"가 본체다.** 집계 로직의 오류는
> 스키마·쿼리·화면이 한 번에 맞아야 안 생기고, 한 계층만 봐서는 절대 안 보인다 —
> 타일과 표를 나란히 놓고 봐야 "어, 이 둘이 왜 다르지?"가 보인다.
