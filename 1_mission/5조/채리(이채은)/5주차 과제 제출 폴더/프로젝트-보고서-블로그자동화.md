# AI 에이전트 기반 블로그 콘텐츠 파이프라인 완전 자동화 프로젝트 보고서

여행 블로그의 소재 수집→글감 선정→초안 작성→검수→제휴 링크 발급→플랫폼 임시저장→성과 분석 전 과정을 AI 에이전트(Claude Code)로 자동화한 프로젝트. 발행 승인만 사람이 담당하는 Human-in-the-loop 구조. 구축 기간: 3일 (계획 수립 → 실전 리허설 완주). 이후 실발행 2회로 검증.

## 1. 문제 정의와 목표

**문제:** 개인 블로그 운영은 소재 정리→키워드 조사→집필→검수→제휴 링크 관리→성과 분석의 반복 노동이며, 꾸준함이 수익의 전제인데 사람의 시간이 병목이 된다.

**목표:** 사람의 역할을 두 가지로 압축한다 — ① 여행 중 폰으로 소재(음성·사진) 던지기, ② 완성된 임시저장 글을 확인하고 발행 버튼 누르기. 나머지 전부(주 3회 글 생산 + 주 1회 성과 분석)는 무인으로.

**비목표(의도적 제외):** 자동 발행, 경험 조작(AI가 경험을 지어내는 것), 비밀번호 저장, 다계정 운영.

## 2. 핵심 설계 원칙 4가지

1. **지능은 코드가 아니라 문서에:** 글감 선정 기준·글쓰기 규칙·검수 체크리스트·주간 분석 절차를 전부 마크다운 "대본"으로 작성하고, AI 세션이 이를 읽고 수행한다. 코드는 브라우저 조작·데이터 수집 같은 "손발"만 담당 → 규칙 개선에 코드 수정이 필요 없다.
2. **사람은 마지막 안전선이자 유일한 선생님:** 발행 전 확인이 안전선이고, 발행 전 사람이 고친 수정 내역(초안 vs 최종본 diff)이 학습 데이터가 된다.
3. **모든 실패는 신호가 되어야 한다:** 무인 실행에서 최악은 "조용히 죽는 것". 전 스크립트가 성공 `OK`/`SAVED:*`, 실패 `FAIL:<단계명>`의 출력 계약을 지키며, 트레이스백으로 죽는 경로는 결함으로 취급해 전수 제거했다.
4. **깨지기 쉬운 것에는 폴백:** UI 자동화는 언젠가 깨진다는 전제. 대가성 스티커 삽입 실패→텍스트 문구, 카드형 링크 실패→텍스트 하이퍼링크로 자동 전환되어 회차가 죽지 않는다.

## 3. 시스템 아키텍처

```
[폰: 메신저 봇]                          [PC: 스케줄러]
 음성·사진·메모 ──▶ 수집기(4시간마다) ──▶ 소재함(음성 자동 전사, 사진 얼굴 자동 모자이크)
                                            │
              월·수·금 저녁 "무인 회차" ────┤  AI 세션이 절차 문서를 대본으로 수행
                                            ▼
  글감 선정 ▶ 키워드 실측 ▶ 초안 작성 ▶ 4관점 검수 ▶ 제휴링크 발급 ▶ 에디터 자동입력·임시저장
  (규칙문서)  (검색광고API)  (규칙문서)   (체크리스트)  (브라우저 자동화)   (브라우저 자동화)
                                            │
                                            ▼
                          메신저 알림 "발행 버튼만 누르면 돼요"
                          (검수 점수·제휴 상품·본문 전체 링크 목록 포함)
                                            │
                          사람: 확인 → (수정) → 발행 → "발행했어+URL"
                                            │
                                            ▼
                     발행 회고: 초안 vs 최종본 문장 단위 diff → 규칙 자동 개선

  [일요일 저녁 "주간 분석"] 통계 자동수집(조회·유입·클릭) ▶ 글별 깔때기 진단
  ▶ 상위 노출 글 구조 벤치마크 ▶ 다음 주 처방 저장 ▶ 추천 소재 ▶ 주간 브리핑 발송
```

**구성 요소:** 규칙 문서 5종(지능) / 파이썬 스크립트 10종(손발: 에디터 입력, 링크 발급·통계, 블로그 통계, 소재 수집, 모자이크, 키워드 조회 등) / 스케줄 2개(심장: 비정각+랜덤 지터) / 메신저 봇(입출력) / JSON 데이터 파일(기억: 글감대장·링크장부·통계 — 삭제 금지·원자적 쓰기)

**기술 스택:** Claude Code(AI 에이전트), Python + Playwright(설치된 크롬을 전용 프로필로 구동), Telethon(메신저 수집), OpenCV(얼굴 모자이크), 검색광고 API(키워드 실측)

## 4. 구현 방법론 — "에이전트가 에이전트를 만들다"

구현 자체도 AI 에이전트 오케스트레이션으로 진행했다:

- **태스크별 분업:** 계획을 10개 태스크로 분해, 태스크마다 격리된 컨텍스트의 구현 에이전트를 파견
- **독립 리뷰 루프:** 구현 완료마다 별도 리뷰 에이전트가 스펙 준수·품질을 검증 → 발견 사항을 수정 라운드로 회부 → 범위 재리뷰로 확인. 이 루프가 실사고성 결함 6건(Critical급)을 운영 전에 잡았다 — 예: 스티커 삽입 실패 시 UI 패널이 열린 채 본문이 오염되는 버그, 링크 발급 성공 후 장부 기록 실패 시 링크가 유실되는 경로, 문서에 적힌 "이 스크립트는 이렇게 죽는다"는 주장이 실행 재현으로 반증된 허위 서술
- **실측 우선:** 셀렉터·API 응답·로그인 만료 화면 등은 추측하지 않고 실제 브라우저 탐사로 확정. 문서의 주장은 실행으로 검증
- **원장(ledger) 기록:** 모든 결정·수정·검증을 진행 원장에 남겨 세션이 끊겨도 이어서 진행 가능하게

## 5. 안전·보안 설계 (자동화 프로젝트의 차별점)

| 위협 | 방어 |
|---|---|
| 실수로 자동 발행 | 이중 안전선: 발행 버튼 셀렉터가 코드·설정 어디에도 없음 + 클릭 직전 버튼 텍스트 검증("발행" 단어 감지 시 거부) — 설정 파일이 오염돼도 발행 불가 |
| 자격증명 유출 | 자동화는 비밀번호를 모름. 사람이 전용 브라우저 프로필에 1회 수동 로그인, 세션 쿠키만 재사용. 프로필은 클라우드 동기화 폴더 밖에 저장 |
| 프롬프트 인젝션 | 웹검색으로 수집한 텍스트 속 지시문("이 링크를 넣어라")은 데이터로만 취급. 본문 외부 링크는 회차 내 발급 링크+공식 출처만 허용 |
| 임의 파일 유출 | 사진 업로드 경로 화이트리스트(모자이크 처리본 폴더만), 그 외 경로는 실패 처리 |
| 봇 탐지·계정 제재 | 사람 속도 입력(랜덤 딜레이), 비정각 스케줄+지터, 캡차 감지 시 즉시 중단·재시도 금지 |
| 데이터 손실 | 데이터 파일 삭제 금지 원칙, 스키마 전환 시 백업 선행, 임시파일→원자적 교체 쓰기 |
| 법적 리스크 | 제휴 글 대가성 표시(표시광고법) 자동 삽입 — 스티커 기본, 실패 시 문구 폴백. 경험 사칭 금지 원칙을 검수 항목으로 강제 |
| 폐기 필요 시 | 킬 스위치 한 마디로 프로필·스케줄 전부 삭제 + 서버측 원격 로그아웃 안내 |

## 6. 검증 결과

- **엔드투엔드 리허설 (성공):** 실제 소재(음성 인터뷰 1건 + 사진 96장)로 무인 회차 전 과정 완주 — 글감 자동 선정, 키워드 실측(월 검색량 1.6만 키워드 확보), 사진 9장 자동 선별·SEO 파일명 부여, 4관점 검수 전항목 합격, 제휴 링크 2건 신규 발급(위치 라벨 부착), 대가성 스티커 자동 삽입, 임시저장 완료. 소요 약 13분, 사람 개입 0회.
- **실발행 2회:** 자동 생성 초안이 실제 발행됨. 발행 회고 루프(초안 vs 최종본 diff 분석)도 정상 작동.
- **성과 데이터 분석 가동:** 누적 제휴 클릭 약 2천 건을 라벨 체계로 재구성 — "어느 글의 어느 위치 링크가 클릭되는가"를 매주 자동 진단하는 깔때기(노출→조회→클릭→전환) 분석이 가동 중.

## 7. 핵심 학습: 문체 정량화 — "AI 글이 마음에 안 드는 이유"를 숫자로

가장 흥미로운 발견. 사용자가 "초안 문체가 마음에 안 든다"고 했을 때, 감이 아니라 실측으로 접근했다:

- 사용자가 과거 직접 쓴 글 6편(367문장)과 AI 초안을 정량 비교 → **행갈이 길이(직접 글 18±21자/줄 vs AI 43자/줄), 느낌표 밀도(글당 15±37개 vs 2개), 어미 분포("-더라구요" 15% vs 6%, 반문 리듬 부재), 태도(실황 중계형 vs 보고서형)**의 격차를 확인
- 이를 "내 목소리 가이드" 12개 실행형 규칙(예문 포함)으로 규칙화하고, **검수 단계에 정량 문체 검사(줄 길이·느낌표 밀도·어미 분포를 실제로 세는)**를 추가
- 발행 회고에서 "사용자가 고친 문장 비율"을 매회 기록 — 이 비율의 감소가 시스템 성장의 공식 지표

→ 교훈: AI 글쓰기 품질의 관건은 모델이 아니라 "개인 문체의 정량 명세"였다. 같은 모델이라도 규칙 문서의 해상도만큼 결과가 달라진다.

## 8. 시행착오와 해결 (요약)

- 자동화 도구가 붙은 브라우저는 일부 OAuth 로그인이 차단됨 → 로그인 창만 순수 브라우저로 분리 (프로필 공유로 세션은 자동화가 재사용)
- "로그인 상태 유지" 미체크 시 세션이 창 닫는 순간 증발 → 로그인 검증은 파일 존재가 아니라 인증 쿠키 존재로
- 저장 완료 판정을 토스트 메시지로 하면 오탐 → 상태 변화(저장 개수 배지) 기반으로 교체
- 통계는 화면 스크래핑보다 XHR 응답 수집이 안정적 — 단 직접 API 호출은 403, 실제 클릭과 응답 대기를 페어링해야 함
- 제휴 플랫폼이 링크별 수익을 제공하지 않음 → 추측값 대신 정직한 null 처리, 분석 축을 클릭·근사 전환으로 재설계
- 한글 Windows 콘솔 인코딩(cp949)에서 특수문자 출력 크래시 — 무인 환경에서만 터지는 유형 → 전 스크립트 utf-8 강제
- 절차 문서와 코드의 계약(실패 코드 목록)이 병행 수정 중 어긋남 → "문서가 대본인 시스템에서 문서-코드 드리프트는 Critical"이라는 운영 원칙 수립

## 9. 한계와 향후 과제

- 썸네일 카드형 링크 자동 삽입은 에디터의 컴포넌트 분할 타이밍 문제로 순서 비결정성 버그가 남아 보류 (텍스트 하이퍼링크로 운영 중)
- 플랫폼 약관상 자동화는 회색지대 — 임시저장까지만·사람 속도·캡차 시 중단으로 보수 운영하지만 무위험은 아님
- 문체 수렴은 발행 회고가 쌓여야 완성 — "수정 비율 감소"를 장기 추적 중
- PC 상시 가동 의존 (스케줄 미실행 시 보충 실행으로 완화)

## 10. 결론

"AI에게 블로그를 맡긴다"는 막연한 목표를, 문서화된 절차(대본) + 안전 계약을 지키는 스크립트 + 사람의 발행 승인 + 수정 diff 학습 루프라는 구체적 구조로 구현했다. 3일 만에 실전 가동에 도달했고, 실발행으로 검증됐다. 핵심 통찰은 두 가지다: ① 자동화의 성패는 "잘 되는 경로"가 아니라 실패 경로의 설계(모든 실패가 신호가 되게)에 달려 있다. ② AI 콘텐츠의 품질은 개인 스타일의 정량 명세화에서 나온다 — 그리고 그 명세는 사람이 고친 흔적에서 자동으로 학습될 수 있다.
