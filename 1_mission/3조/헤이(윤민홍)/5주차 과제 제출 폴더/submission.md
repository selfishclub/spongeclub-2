## 🎯 과제 1. 구현, 그 다음의 것

![과제 1 안내](https://github.com/selfishclub/spongeclub-2/raw/main/_meta/week5/mission1.png)

> 만드는 건 끝났는데 — 그 다음이 진짜 시작이에요 (답이 안 나와 있어도 OK, 고민을 꺼내놓는 것 자체가 과제)

- **지금 걸려 있는 고민 하나:**

  **배포하면 생성 비용이 전부 내 API 키로 청구된다.**

  막상 돌아가는 앱이 나오니 고민이 세 개 남았는데, 그중 실제로 나를 멈춰 세운 건 이거였다.

  | 남은 고민 | 해결 방향 |
  | --- | --- |
  | 만들고 나서 결국 손으로 인스타에 올리고 있다 | 앱 안에서 쓰레드·인스타 직접 게시까지 (자동 게시를 선택 기능이 아니라 필수 요건으로 승격) |
  | 사진만으로는 요즘 피드에서 밀린다 | 영상 슬롯 = 이번 기수 최종 목표로 확정 |
  | **배포하면 생성 비용이 내 API 키로 청구된다** | **정식 가동 보류.** 입장코드 + 일일 한도 + 콘솔 월 한도를 방어선으로 먼저 만들어두고, 기능이 더 여문 뒤 키 연결 |

- **그게 왜 고민인지 (무엇이 걸리는지):**

  아티팩트로는 자동 게시가 원천적으로 안 돼서 Vercel로 옮기기로 했다. Vercel은 처음이라 한 단계씩 밟아 가입·포팅·로컬 구동까지 성공했다. 그런데 마지막에 API 키를 붙이려는 순간, **베타 테스터가 누르는 생성 버튼 비용이 전부 내 키로 청구된다**는 걸 체감했다.

  기능은 다 만들어놨는데, 켜는 순간부터 남이 쓰는 만큼 내가 돈을 낸다. 그래서 **여기서 멈추는 게 맞다고 판단**했다.

- **어떻게 풀어볼 생각인지:**

  방어선을 **먼저** 만들어두고 키는 나중에 붙인다.
  - 입장코드 — 아무나 못 들어오게
  - 일일 생성 한도 — 한 사람이 하루에 쓸 수 있는 양 제한
  - 콘솔 월 한도 — 최악의 경우에도 월 상한이 넘지 않게

  당분간은 기존 공개 링크로 테스트를 돌린다. Vercel 프로젝트는 지우지 않고 **대기 상태**로 뒀다.

- **필요한 게 있다면 무엇인지:**

  _(아직 못 채움)_

## 🏁 과제 2. 구현 마무리 + 실제 유저 피드백 받기

![과제 2 안내](https://github.com/selfishclub/spongeclub-2/raw/main/_meta/week5/mission2.png)

> 시작할 때 "이번엔 이건 꼭 만들겠다" 했던 것 — 지금 어디까지 왔나요? (스폰지클럽 내 유저피드백 모집 가능)

- **최종 완성한 것 (지금 어디까지):**

  **이번 기수 안에 반드시 완성할 것 = 영상 슬롯(사진 + 영상 혼합)**
  카드 슬롯에 사진뿐 아니라 짧은 영상도 넣어, 카드1=영상 / 카드2=사진 식으로 섞인 피드·릴스를 뽑는 것. 이걸 기수 내 최종 목표로 확정했다.

  이번 주 완성분:
  - **모바일 사진 업로드 버그 수정** — 폰에서 사진이 안 올라가던 문제를 잡음 (업로드 이미지 1600px 축소 + 색 추출 실패 시 폴백). 코드는 완료, 게시본 반영은 다음 주
  - **Vercel 배포본 포팅** — AI 호출을 `/api/generate` 서버리스 함수로 옮겨 API 키를 브라우저에 노출하지 않도록 하고, 입장코드·일일 생성 한도를 붙임. 로컬 구동까지 확인

- **🚀 실제 배포 URL:**

  https://claude.ai/public/artifacts/f2dafd05-6cef-4cf6-aca1-e02b1d60da43 _(지금 바로 써보기)_

  → Vercel 배포본은 위 API 키 비용 문제로 **정식 가동 보류 중**이다.

- **결과물 (링크·스크린샷 — 이미지는 `이미지첨부/` 폴더에):**

  라이브 링크: https://claude.ai/public/artifacts/f2dafd05-6cef-4cf6-aca1-e02b1d60da43

- **받은 유저 피드백:**

  - **외부 이미지 업로드 + 영상도 들어갈 수 있게 "플렉스 홀더"로** — 슬롯을 사진 전용으로 고정하지 말고, 사진이든 영상이든 유연하게 받는 형태로 만들어보라는 의견
  - **아카이빙 기능이 필요하다** — 만든 결과물을 다시 꺼내볼 수 있어야 한다는 것
  - **표지 후킹** — 귀여운 요소, 움직임 등으로 첫 화면에서 눈길을 잡아야 한다는 것

  → 첫 번째 피드백이 내가 최종 목표로 잡은 **영상 슬롯**과 같은 방향이라 확신이 생겼다. 다만 "슬롯을 사진/영상으로 나눠 만들 것"이라고 생각했는데, **하나의 홀더가 둘 다 받게** 하는 쪽이 더 낫겠다는 힌트를 얻었다. 아카이빙과 표지 후킹은 생각해보지 못한 것이라 다음 단계 후보로 적어둔다.

## 🔧 삽질 과정

> 막혔던 지점, 시도한 방법, 해결 과정을 솔직하게 적어주세요.

**1. 모바일에서 사진이 안 올라감**

PC는 멀쩡한데 폰에서만 "사진 처리 중…"에서 멈췄다. 코드를 뒤져 원인 두 개를 찾음 — ① EXIF 제거를 원본 해상도 그대로 캔버스에 그려서 모바일 브라우저 메모리 한계에 걸림 ② 색 추출용 이미지에 실패 처리(onerror)가 없어 한 장이라도 안 읽히면 무한 대기. 축소 + 실패 시 기본색 폴백 + 타임아웃으로 해결.

**2. 배포까지 갔다가 되돌아옴**

아티팩트로는 자동 게시가 원천적으로 안 돼서 Vercel로 옮기기로 했다. Vercel은 처음이라 한 단계씩 밟아 가입·포팅·로컬 구동까지 성공. 그런데 마지막에 API 키를 붙이려는 순간, 베타 테스터가 누르는 생성 버튼 비용이 전부 내 키로 청구된다는 걸 체감. **여기서 멈추는 게 맞다고 판단**하고, 당분간은 기존 공개 링크로 테스트를 돌리기로 했다. 프로젝트는 지우지 않고 대기 상태로 둠.

**3. 링크가 자꾸 죽었던 이유**

게시 취소는 되돌릴 수 없고, 다시 게시하면 주소가 새로 발급된다는 걸 뒤늦게 알았다. 그동안 제출글에 넣어둔 링크가 계속 404였던 원인. 최종 링크를 정한 뒤엔 그 아티팩트를 건드리지 않기로.
