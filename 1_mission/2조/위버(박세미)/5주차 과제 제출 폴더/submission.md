## 🎯 과제 1. 구현, 그 다음의 것

![과제 1 안내](https://github.com/selfishclub/spongeclub-2/raw/main/_meta/week5/mission1.png)

> 만드는 건 끝났는데 — 그 다음이 진짜 시작이에요 (답이 안 나와 있어도 OK, 고민을 꺼내놓는 것 자체가 과제)

- **지금 걸려 있는 고민 하나:**
  티키타의 핵심 규칙은 **"대화 중엔 질문만, 답은 카드에서"**인데, 이걸 지금은 프롬프트로만 붙잡고 있다. LLM은 구조적으로 도와주려 하기 때문에, 대화가 길어지거나 사용자가 "그래서 어떻게 해야 해?"라고 직접 물으면 모델이 조언 쪽으로 새기 시작한다. 그런데 규칙이 지켜지고 있는지 확인할 방법이 지금은 **내가 직접 읽어보는 것뿐**이다.

- **그게 왜 고민인지 (무엇이 걸리는지):**
  이 서비스의 존재 이유가 기능이 아니라 **"판단받지 않는 자리"**라는 관점 하나이기 때문이다. 조언이 한 번 새어나오는 순간 티키타는 그냥 또 하나의 챗봇이 된다. 즉 품질 문제가 아니라 **정체성 문제**다. 그런데 프롬프트 기반 제약은 검증이 안 된 채로 "잘 되는 것 같다"에 머물러 있다.

- **어떻게 풀어볼 생각인지:**
  ① 조언이 새는 패턴을 케이스로 모은다 — 사용자가 답을 직접 요구할 때, 위로를 요구할 때, 7턴을 넘길 때
  ② 그 케이스를 **회귀 테스트 세트**로 만들어서, 프롬프트를 고칠 때마다 같은 입력으로 돌려보고 조언이 섞였는지 확인한다
  ③ 프롬프트로 못 지키는 건 흐름으로 막는다 — "정리해줘" 버튼처럼, 답이 필요할 땐 대화가 아니라 카드로 빠지게

- **필요한 게 있다면 무엇인지:**
  내가 아닌 사람의 실제 대화 로그. 나는 이 서비스의 규칙을 알고 쓰기 때문에, 규칙을 깨는 방향으로 물어보지 않는다. **모르고 쓰는 사람의 대화**가 있어야 어디서 새는지 보인다.

## 🏁 과제 2. 구현 마무리 + 실제 유저 피드백 받기

![과제 2 안내](https://github.com/selfishclub/spongeclub-2/raw/main/_meta/week5/mission2.png)

> 시작할 때 "이번엔 이건 꼭 만들겠다" 했던 것 — 지금 어디까지 왔나요? (스폰지클럽 내 유저피드백 모집 가능)

- **최종 완성한 것 (지금 어디까지):**
  시작할 때 목표는 **"질문할 줄 몰라도 대화가 시작되는 자리를 만든다"**였다. 지금 상태는 이렇다.
  - ✅ **PRD 완성** — 문제 · 페르소나(30대 여성/커리어 지속/내향) · 가치 · 기능 · 성공기준 · 범위 · 장기비전
  - ✅ **7턴 대화 설계** — 막막함 → 구체적 장면 → 감정 → 그 밑 생각 → 재구성 → 진짜 원함 → 스스로 한 줄 정리
  - ✅ **무백엔드 단일 HTML MVP** — 설치·서버·로그인 없이 더블클릭 실행. 체험 모드(API 키 없이 전체 흐름) + 실제 AI 모드(Claude API 키 입력 시 전환) 이중 구조
  - ✅ **말투 선택(반말/존댓말)** — 가상 페르소나 피드백에서 나온 "낯선 상대인데 반말이 불편하다"를 반영해 추가
  - ✅ **정리 카드** — JSON 스키마로 강제해 **AI 문장이 아니라 사용자 발화**를 인용하도록 설계
  - 🔜 **웹 배포** — 이번 기수 안엔 못 넘김 (아래)

- **🚀 실제 배포 URL:**
  없음 — 로컬 단일 HTML로만 동작한다. API 키를 사용자 브라우저에만 두는 무백엔드 구조라서, 공개 배포를 하려면 키 처리 방식부터 다시 설계해야 한다. "일단 배포"가 안 되는 형태로 MVP를 짠 게 이번 기수의 구조적 병목이었다.

- **결과물 (링크·스크린샷):**
  4주차 제출 폴더에 전체 산출물이 있다.
  - `PRD-coffeechat-ai.md` — 전체 PRD
  - `conversation-design-coffeechat.md` — 7턴 대화 설계 + 복붙용 시스템 프롬프트 2종(대화용·카드생성용)
  - `index.html` — 작동하는 단일 HTML MVP (더블클릭 실행)
  - `README.md` — PRD 6요소 요약 + 실행법

- **받은 유저 피드백:**
  실제 유저 피드백은 결국 받지 못했다. 이유는 명확하다 — **배포가 안 됐기 때문**이다. 로컬 HTML이라 "한번 써봐"라고 링크를 던질 수가 없고, 파일을 보내서 열게 하는 순간 이미 부담이 생긴다. **"내향적인 사람도 부담 없이"가 이 서비스의 전제인데, 정작 전달 방식이 가장 부담스러운 형태였다.** 이게 이번 기수에서 제일 아픈 지점이다.
  대신 통계 기반 합성 페르소나 4인 패널 인터뷰로 검증했고, 거기서 나온 세 가지가 실제 반영됐다.
  - "낯선 상대인데 반말이 불편하다" → **말투 선택 기능** 추가
  - "7턴이 부담될 수 있다" → **"짧게 끝내도 된다"**를 인트로에 명시, '정리해줘' 상시 노출
  - "이거 무료 맞나? 데이터 팔리는 거 아냐?" → "광고도 판매도 없고 대화는 이 브라우저에만 남는다"를 인트로에 명시

## 📣 과제 3. SNS에 남기기

![과제 3 안내](https://github.com/selfishclub/spongeclub-2/raw/main/_meta/week5/mission3.png)

> 구현했던 것들 + 그 다음 단계에 대한 생각 (아끼면 아무 일도 안 일어나요 — 꺼내놓는 순간 가장 많이 남아요)

- **구현했던 것들 (무엇을 / 어떻게 굴러가는지 / 뭐가 달라졌는지):**
  **티키타(Tikitah)** — 챗GPT는 "물어보는 도구", 티키타는 **"물어봐주는 서비스"**다. 빈 채팅창 대신 상황 카드 하나를 고르면 AI가 먼저 질문을 던지고, 7턴 대화가 끝나면 **내가 한 말에서 뽑은 문장**으로 정리 카드가 만들어진다. 백엔드 없이 단일 HTML로 돌아간다.

  만들면서 남은 것 세 가지:
  - **"기능"이 아니라 "관점"이 서비스를 만든다.** 같은 챗 UI인데 *"내가 묻는다" → "AI가 물어봐준다"*로 방향만 뒤집으니 완전히 다른 자리가 됐다.
  - **"배경 없음"을 한계가 아니라 가치로 재정의**한 게 기획의 핵심이었다. 친구는 나를 알아서 판단하지만("너 원래 그러잖아"), 티키타는 나를 모르니 구조적으로 판단이 불가능하다. 그래서 처음 겪는 고민을 검열 없이 꺼낼 수 있다.
  - **AI에게 조언을 *시키지 않는 게* 제일 어려웠다.** LLM은 자꾸 도와주려 한다. 그걸 막는 장치(질문만·되묻기·판단 금지)가 이 서비스의 난이도이자 정체성이다.

- **다음 단계 생각 (뭘 더 하고 싶은지 / 남은 것 / 어디로):**
  가장 먼저 **배포**. 이번 기수에서 제일 크게 배운 건 "만들었다"와 "누가 쓸 수 있다" 사이의 거리였다. 로컬에서 완벽하게 도는 것보다, 링크 하나로 열리는 미완성이 훨씬 멀리 간다. 다음엔 **배포 가능한 형태를 먼저 정하고 기능을 얹겠다.**
  그다음은 조언이 새는 지점을 케이스로 잡아 **회귀 테스트로 만드는 것**(과제 1). 그리고 장기적으로는 쌓인 정리 카드를 바탕으로 **실제 사람과 연결**하는 것 — 티키타가 최종 목적지가 아니라, 결국 사람과의 커피챗으로 넘어가는 다리가 되는 게 원래 그리던 그림이다.
