# ① 온마음 말씀사진관

### 제목
```
온마음 말씀사진관
```

### 한줄 소개
```
어르신 사진을 찍어 성경 말씀과 합성해, 그 자리에서 인쇄해 드리는 설치 없는 웹 포토부스
```

### 대표 이미지
`1_mission/2조/배짱(박종배)/3주차 과제 제출 폴더/이미지첨부/말씀사진관/` 폴더에서 골라 업로드

- **대표**: `19-이의복.png` (올해 아흔, 실제 현장 사례로 스토리가 붙어 있음) 또는 `01-안순연.png`
- **추가 스크린샷 4장 추천**:
  - `05-김봉연.png`, `11-손달순.png`, `16-임숙자.png` — 실제 인쇄 카드
  - + 앱 화면 캡처 1장 (아래 "찍어야 할 것" 참고)

### 설명
```
■ 어떤 문제를 해결하려고 만들었나

선교의 가장 큰 한계는 "팀이 떠나면 끝"이라는 것이었습니다. 삼일교회 영덕·울진 선교팀으로
어르신들을 만나면서, 그 자리에서 드릴 수 있는 게 없다는 게 계속 마음에 걸렸습니다.
그래서 (1) 앱 설치·계정 없이 태블릿 브라우저만으로 되고, (2) 선교팀이 떠난 뒤에도
교회가 계속 굴릴 수 있는 시스템을 목표로 만들었습니다.

■ 주요 기능

· 성함 입력 → 페이지 내 카메라(전면/후면·3초 타이머)로 촬영
· 사진 + 성함 + 오늘의 말씀 + 교회명을 세로 카드로 자동 합성 (말씀 풀 100구절)
· 블루투스 감열 프린터로 즉석 인쇄 — Web Bluetooth로 프린터 프로토콜을 직접 구현
  (0x51 0x78 헤더 + CRC8 패킷, 행 단위 비트맵 전송)
· 플로이드-스타인버그 디더링으로 1비트 흑백 변환 — 미리보기와 인쇄물이 동일
· 역광 보정(지역 적응 명암) + 언샤프 마스크 선명화
· 🖼 기기내 갤러리 — 인쇄한 카드의 컬러 원본을 IndexedDB에 자동 보관 (서버 없음 = 비용 0, 유출 0)
· 🙏 기도제목 직접 입력 / ✍️ 사진 없이 말씀+이름만 카드 (촬영이 부담스러운 어르신용)
· ⚙ 진단 도구(테스트 인쇄·용지 이송·로그) + 교회 비치용 운영 가이드 6단계

■ 실제 사용 현황

평해감리교회 118주년 기념예배에서 어르신 18분 · 19장을 현장에서 찍어 인쇄해 드렸습니다.
현재 평해감리교회에 비치·운영 중이고, 전의무학교회·회사 로비 설치 예정,
일본 선교팀에서도 검토 중입니다.
같은 엔진에 콘텐츠만 바꿔 회사 로비용 「굿모닝라이언 행운 사진관」으로도 확장했습니다.
→ https://baezzanglion.github.io/sponge-intro/lion.html

■ 어려웠던 점 / 배운 점

1. "연결됐는데 출력이 안 된다"의 범인은 프로토콜이 아니라 감열지 방향이었습니다.
   소프트웨어 하던 사람은 소프트웨어부터 의심하더군요. 물리적인 것부터 봤어야 했습니다.
   대신 그 삽질 덕분에 진단 기능(급지 테스트·로그)이 태어났습니다. 삽질은 기능이 됩니다.

2. 하드웨어는 겉모양이 아니라 칩셋입니다. 브랜드 제품(PeriPage·Paperang)이 오히려
   독자 프로토콜이라 웹 연동 불가였고, 영수증형은 블루투스 클래식이라 Web Bluetooth
   연결 자체가 안 됐습니다. "구매 전 판매자에게 블루투스 기기 이름 묻기" 한 줄이
   시스템 성립 조건이었습니다. 공급망 조사도 개발이었습니다.

3. 유저 피드백이 코드가 되는 순간이 짜릿했습니다. 실사용자의 "원본(컬러)으로 저장되면
   좋겠다"와, 가상 페르소나 목사님의 "감열지 글씨가 날아가면 안 드린 것만 못하다"가
   같은 곳을 가리키고 있었습니다. 그날 바로 컬러 원본 갤러리를 붙였고, 그게
   "즉석본은 감열지, 보관본은 폰에 컬러로"라는 이중 구조가 됐습니다.

4. 하드웨어 제약은 콘셉트로 뒤집을 수 있습니다. 흑백 디더링 = 옛날 신문 감성,
   바래는 감열지 = 매주 새로 받는 리추얼.

5. 시스템의 끝은 배포가 아니라 운영 가이드입니다. 사모님이 충전하고 용지를 갈 수 있으면
   시스템이고, 아니면 데모입니다.
```

# ② 온마음 이야기 노래 스튜디오

### 제목
```
온마음 이야기 노래 스튜디오
```

### 한줄 소개
```
어르신의 인생 이야기를 실시간으로 받아 적어, 세상에 하나뿐인 헌정곡을 만들어 드리는 웹앱
```

### 대표 이미지
**아직 캡처 없음 — 직접 찍어야 합니다.** (아래 "찍어야 할 것" 참고)

### 설명
```
■ 어떤 문제를 해결하려고 만들었나

삼일교회 영덕·울진 선교의 어르신 사역에서, 봉사자가 마사지해 드리며 5~10분씩 인생
이야기를 나눕니다. 그 이야기로 "세상에 하나뿐인 나의 노래"를 만들어 드리면
"하나님이 당신을 개별적으로 아신다"는 메시지가 그대로 전달됩니다.
문제는 수작업으로는 60~90분 안에 불가능하다는 것이었습니다.
그래서 이야기 수집 → 가사 생성까지의 병목을 자동화했습니다.

■ 주요 기능

· 성함 · 곡 분위기(찬양/신나는 트로트/잔잔한 트로트/발라드) · 보컬(여성/남성/아이/가족) 선택
· Web Speech API(ko-KR) 실시간 받아쓰기 — 손글씨 폰트로, 봉사자용 질문 가이드 카드 6종 순환
· Claude(Opus)가 이야기를 요약해 맞춤 가사 생성 — 어르신 성함이 후렴에 반복되도록 설계
· Suno 스타일 프롬프트 자동 생성 → Suno에 붙여넣기(30초) → 완성곡 QR 생성해 포토카드 뒷면 인쇄
· 봉사자 20여 명이 각자 스마트폰 브라우저로(앱 설치 없음), 운영자 1명만 Suno 담당하는 분산 구조
· API 키 미배포를 위한 Vercel 서버리스 프록시 + 팀 코드 인증
· 음성 인식 불가 환경을 위한 텍스트 입력 폴백

■ 실제 만들어 드린 노래

· 이의복 어르신(올해 아흔) — 아내 황고분 어머님과의 한평생, 아내의 회복을 위한 기도
  https://suno.com/s/5mAsCRjn3O8oSdGE
· 송분선 어머님 — 울진 평해 학곡리로 시집와 네 남매를 키운 팔십 평생 (트로트/CCM 2버전)
  https://suno.com/s/MqyRwwYUlvM2Mpyg
  https://suno.com/s/vUCCIyUrbA4mO58t

  [Chorus] 송분선 송분선 우리 어머니 / 아들 둘 딸 둘 잘도 키웠네
           송분선 송분선 꽃 같은 인생 / 얼씨구 좋다 복이 넘치네

■ 어려웠던 점 / 배운 점

1. AI 재량과 결정적 코드의 경계가 품질을 만듭니다. 스타일 프롬프트를 AI에게 맡겼더니
   "찬양"을 골라도 "Korean trot"이 섞여 나왔습니다. 분위기×보컬 확정 템플릿(MOODS 맵)으로
   코드에 이관하니 사라졌습니다. 핵심은 "무엇을 생성시키지 않을 것인가"였습니다.

2. 웹 표준 기술은 모바일에서 파편화됩니다. 카톡 인앱 브라우저 마이크 권한 무한 팝업,
   MediaRecorder ↔ SpeechRecognition 마이크 충돌, 안드로이드 크롬 받아쓰기 중복 누적…
   실사용 환경(카톡) 테스트가 개발의 절반이었습니다.

3. 자동화의 목표는 100%가 아니라 병목 제거입니다. Suno는 공식 API가 없어 자동화 범위를
   "가사·스타일 생성"까지로 긋고 입력 30초만 수동으로 남겼습니다. 그 30초가 오히려
   품질 검수 지점이 됐습니다. 복구 불가능한 의존성은 현장에 두지 않습니다.

4. 제약(60~90분 · 운영자 1명 · 비개발자 20명)을 먼저 수치화하고 역산하는 설계가
   기능 목록보다 중요했습니다.

# ③ 마음배달 — 마니또 OS

### 제목
```
마음배달 — 서로가 서로를 챙기는 마니또 OS
```

### 한줄 소개
```
누군지 모른 채 챙기고 마지막 날 밝혀지는, 조원끼리 서로를 챙기게 만드는 익명 마니또 웹앱
```

### 대표 이미지
**아직 캡처 없음 — 직접 찍어야 합니다.** (아래 "찍어야 할 것" 참고)

### 설명
```
■ 어떤 문제를 해결하려고 만들었나

인터뷰 스킬로 저를 파고들었더니 이런 문장이 나왔습니다 —
"2조도 회사 팀원도, 챙기는 걸 혼자 다 짊어지고 내 책임이라 생각한다."
바쁜 주엔 조원 챙김이 제일 먼저 밀렸고 미안함이 남았습니다.
문제는 제가 열심히 안 하는 게 아니라, 모든 게 나 하나에 걸려 있는 구조였습니다.
그래서 "내가 다 안 해도 굴러가는, 서로 챙기는 판"을 만들었습니다.

■ 주요 기능

앱 2종 + 운영 OS 1종으로 구성됩니다.

1) 마음배달 봉투 웹앱 (https://maeumbaedal.vercel.app)
   · 무백엔드 정적 웹앱. 랜딩(치즈 우체부 히어로) → '봉투 탭해서 열기' →
     "이번 주 챙길 마니또 + 앵커 미션" 카드까지 한 흐름
   · 개인 봉투 링크를 DM으로 전달 — 익명성 유지

2) 마니또 추리 대회 웹앱 (https://maeumbaedal-quiz.vercel.app)
   · 참가자가 "전체 배정표"를 예측해 봉인 제출 → 발표일에 운영자가 채점, 순위·시상
   · 방(room) 단위로 조를 완전 분리 — URL의 ?room= 값만 바꾸면 여러 조가 한 앱을 동시 사용
   · 정답(실제 배정)은 서버에 저장하지 않고 브라우저에서만 채점 → 익명성 보장

3) 운영 OS — Claude 프로젝트 「마음배달 운영 지침 v1.1」
   · 역할·핵심가치·페르소나·진행구조·톤가이드·에셋목록
   · 오프닝 공지문 / 킥오프 DM / 주간 앵커 미션 풀 / 발표 진행문 / 브랜드 애셋
   · 프로젝트 지침에 붙여 매번 같은 품질로 반복 운영

■ 설계의 핵심

· 두 가지 가치: ①몰래 그러나 진심 (익명이 부끄러움을 덜어 오히려 솔직한 응원을 꺼내게 함)
  ②드러나는 재미 (추측하고 밝혀지는 과정 자체가 이벤트)
· 관망하는 사람을 설득하지 않습니다. 먼저 움직이는 두 엔진(조용한 성실러·리액션 요정)이
  판을 만들면 나머지가 저절로 스며드는 "줄 서는 가게" 구조로 설계했습니다.
· 성공 지표는 매출·전환이 아니라 참여자의 연결과 온기입니다.
  '누군가 나를 챙기고 있다'는 감각이, AI 공부를 혼자가 아니라 함께 완주하게 만듭니다.

■ 어려웠던 점 / 배운 점

1. 익명 챙김이 '감시·스토킹'으로 읽힐 위험이 있었습니다. 톤 규칙으로 못박았습니다 —
   '지켜본다' 뉘앙스 금지, 프레임은 언제나 '마음을 배달하기'.
   '몰래'는 🤫·'살짝'·'한 스푼' 같은 장치로 귀여운 비밀로 전환했습니다.

2. 2주차라는 낯선 시점의 참여 저조가 걱정이었는데, 관망자를 설득하는 대신
   먼저 즐겁게 움직이는 엔진이 판을 만드는 구조로 풀었습니다.

3. 익명성은 기능이 아니라 아키텍처였습니다. 추리 대회에서 정답을 서버에 저장하지 않고
   브라우저에서만 채점하게 만든 것 — 저장하지 않으면 샐 수도 없습니다.

4. 신념이 실행 과제가 되는 경험이었습니다. "서로가 서로를 위하면 해결된다"는 막연한 믿음이,
   인터뷰를 거치며 "혼자 짊어지는 구조를 바꾸자"는 구체적인 판으로 바뀌었습니다.
```

### 배포 링크
```
https://maeumbaedal.vercel.app
```
> ※ 칸이 하나뿐이라 봉투 앱을 넣었고, 추리 대회 앱(https://maeumbaedal-quiz.vercel.app)은 설명에 포함시켰습니다.

### 사용 기술/도구 (체크)

```
■ 어떤 문제를 해결하려고 만들었나

그래서 담당자 개인기가 아니라 팀 누구나 돌릴 수 있는 솔루션으로 만들었습니다.

■ 주요 기능 — 6단계 파이프라인

인테이크 → 컴플라이언스 게이트 → 전략 디벨롭 → 콘텐츠 → 제작 → 학습

5. 결정은 대화가 아니라 파일에 삽니다. 히스토리를 두 번 날려먹고 나서,
   확정된 결정은 즉시 가이드에 명문화하고 git을 정본으로 삼았습니다.
