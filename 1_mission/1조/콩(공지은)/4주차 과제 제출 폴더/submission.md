## 🎯 과제 1. PRD 기획 및 구현
> 주요 가치 · 페르소나 · 소구 방식을 담은 PRD → 구현까지

- **주요 가치:**

  > **"믿기 전, 한 번의 허들을."**

  AI는 MECE하게 정리해줄 뿐, 판단은 결국 내 몫인데도 결과를 그대로 받아들이기 쉽다. 히든 프레임은 기사·유튜브·텍스트 링크를 붙여넣으면 그 글이 당연하게 깔고 가는 숨은 전제(감정 자극·생략·성급한 일반화·당연시·인과 단정·대표성 왜곡·이분법 7종)를 짚어주는 비판적 사고 훈련 앱이다. `deep-interview` 스킬(8라운드, 모호성 100%→18%)로 "중립은 위험하다"는 철학과 "AI가 판단 전에 허들을 만들어줄 수 있다"는 가설을 구체적인 스펙으로 정제했다.

- **페르소나:**

  > 뉴스·유튜브·SNS 콘텐츠를 소비할 때 "그래서 뭐가 문제인데?"를 스스로 짚어내기 어려운 일반 콘텐츠 소비자. 링크를 붙여넣기만 하면 되는 낮은 진입장벽이 필요하다.

- **소구 방식:**

  > 분석을 바로 보여주지 않고, **"추리해보세요"** 화면에서 내가 먼저 숨은 전제를 추측하게 한 뒤 AI 분석과 비교해 놓친 지점(놓침/부분일치)과 "내가 쓴 안경"(나의 편향)을 짚어준다. 정답을 알려주는 도구가 아니라, 스스로 놓친 지점을 발견하게 만드는 방식.

- **구현한 것 (링크·스크린샷):**

  📎 [1조_콩_히든프레임.app.pdf](1조_콩_히든프레임.app.pdf)

  - **핵심 플로우 4단계**: 메인(링크/사진/파일 입력) → 추리해보세요(분석 전 내 추리 먼저) → 화자의 숨겨진 의도(내 추리 vs AI 분석 비교 + 내가 쓴 안경) → 지난 경계 보기(내가 자주 놓친 프레임 통계)
  - 실제로 화면을 써보면서 뒤로가기 버튼 추가, 불필요한 원형 디자인 요소 제거, 버튼 색상 변경, 제목을 "히든 프레임"으로 확정하는 등 디테일을 대화형으로 디벨롭
  - 스택: Expo(React Native) + Supabase + Claude API — 비개발자가 Windows에서 클라우드 빌드로 배포 가능한 조합
  - `expo-env.d.ts`가 빈 파일로 export되어 타입체크가 깨졌던 것을 발견해 원래 내용으로 복구
  - 로고는 Claude보다 그림을 잘 만드는 GPT로 별도 제작
  - 이번 주 세팅 작업: 비개발자 입장에서 OMC(oh-my-claudecode) 플러그인을 `/omc-setup`으로 초기 설정 — Agent Teams·HUD·기본 실행 모드(ultrawork)까지 활성화하고, autopilot·ralph·deep-interview·debug·trace 등 스킬을 "쉬운 설명 + 예시" 표로 정리해 필요할 때 꺼내 쓰기로 함

## 🗣 과제 2. 유저 피드백 받기
> 실제 2명 이상 + 플러스 알파로 가상 페르소나

- **실제 유저 피드백 (2명 이상):** 🟡 진행 예정 — 아직 실제 유저 피드백을 받지 못했다. 가상 페르소나 피드백에서 나온 이탈 지점(추리 화면 부담감)을 먼저 반영한 뒤, 실제 유저 2명 이상에게 온보딩 흐름을 그대로 테스트받을 예정.
- **가상 페르소나 피드백:** 허깅페이스 `nvidia/Nemotron-Personas-Korea`(한국어 합성 페르소나, 100만 레코드) 데이터셋 활용법을 배우고, `virtual-customer-feedback` 스킬로 가상 고객 2명(경찰관 최동현 33세·전업주부 신은경 35세)을 뽑아 온보딩 4단계(입력→추리→로딩→결과)를 롤플레이 시켜봄. 최동현은 전 단계 통과. 신은경은 "추리해보세요" 단계에서 "시험 보는 기분"이라 건너뛰기로 이탈.
- **피드백에서 알게 된 것:** "추리해보세요" 화면이 의도와 달리 정답이 있는 시험처럼 느껴질 수 있다는 걸 확인 — "정답 없음" 안내 문구를 추가하기로 결정. 단, 이건 합성 데이터 기반 시뮬레이션 결과이지 실제 검증이 아니므로, 실사용자 테스트 전 이탈 지점을 미리 걸러내는 사전 점검 용도로만 쓰고 그대로 "검증 완료"로 보고하지 않기로 함.
