v1.3 변경 요약 — 포지션 전환

가상 페르소나 10인(아웃바운드 5 · 인바운드 5)에게 v1.2 프로토타입을 사용시켜 검증한 결과, 10명 중 6명의 준비물 1순위가 옷이 아니었다. 옷차림은 목적이 아니라 준비의 한 레이어였다. 이에 따라 제품을 '여행 옷차림 추천' → '여행 준비'로 재정의하고 다음을 반영했다. ① 지참 리스트를 여행 준비 리스트로 확장(여권·충전기·상비약 자동 생성), ② 비교 기준 도시와 온도 단위를 사용자 기준으로 자동 판정(서울·섭씨 하드코딩 제거), ③ 여행 목적 칩 13종 도입, ④ 성별 입력·저장 리스트·텍스트 복사, ⑤ 한국어/English 전환(인바운드 대응), ⑥ 목적지 검색 정확도 재설계, ⑦ 화면 3분할(검색·준비 리스트·저장), ⑧ Vercel 프로덕션 배포.

v1.2 요약 (이전)

Phase 1 프로토타입 구현. ① 레퍼런스 검색에 실제 기온대 키워드 주입, ② 코디·옷장 플래너 화면 통합, ③ 사진 색감 스타일 분석, ④ 목적지·문화 팁 확장, ⑤ DIVE 스타일 디자인 시스템.

① 문제 정의

누가·언제·어떤 상황에서: 해외여행을 앞둔 여행자가, 여행 확정 후부터 짐 싸기 직전까지, 목적지의 그 시기 날씨와 적절한 옷차림을 판단하지 못하고 있다. 일기예보는 출발 직전에야 유효하고, "최고 14도"라는 숫자만으로는 무엇을 입을지 감이 오지 않는다.

지금은 어떻게 버티고 있는가(대체재): "3월 파리 옷차림" 블로그 검색 — 몇 년 전 글, 광고성 콘텐츠, 글마다 다른 결론. 결과적으로 불안해서 옷을 과잉으로 싸간다.

② 주요 페르소나

상황으로 정의: 스타일 기준이 뚜렷한 30대 디자이너. 여행 옷차림도 취향에 맞아야 하지만, 목적지 날씨에 대한 확신이 없어 "혹시 몰라" 옷을 계속 추가하다가 캐리어가 넘친다. 도시 여행과 그랜드캐년 같은 액티비티 여행을 모두 다닌다.

"결국 옷을 너무 많이 싸가서 반은 안 입었어."

v1.3 — 두 축으로 재설정

검증 완료

단일 페르소나로는 이 제품의 실패 지점이 드러나지 않았다. 아웃바운드(국내→해외)와 인바운드(해외→국내) 두 축으로 10인 패널을 다시 구성해 프로토타입을 사용시켰다.

  • 아웃바운드 — 도톤보리 미식 여행자(23), 랜드마크 도장깨기(33), 제주 가족 여행(45), 부산 감성 기록(36), 기장 숲길(50)
  • 인바운드 — 스프레드시트로 벚꽃을 설계하는 싱가포르인(20), 파타고니아를 다녀온 미국인 연구자(29), 여행을 프로젝트처럼 다루는 싱가포르인(39)

여기서 v1.2가 "서울에 살고, 사계절 옷장을 갖췄고, 섭씨로 사고하는 사람"을 암묵적 기준 사용자로 가정하고 있었다는 것이 드러났다. 인바운드 페르소나에게 추천 4벌은 전부 미보유 항목이라 리스트가 패킹이 아니라 쇼핑 목록이 되었고, 미국인 페르소나는 "12°C"가 추운지 선선한지 판단하지 못했다.

"싱가포르보다 평균 최고 24도 낮아요. 지금 옷장에 있는 옷으로는 대응할 수 없는 온도예요." — 이 앱이 인바운드 사용자에게 해야 할 한 문장

③ 주요 가치 · 소구 방식

지키는 것 한 줄추측이 아니라 근거(10년 기후 데이터 + 같은 시기 여행객들의 실제 옷차림)로 옷을 결정하게 한다.
페르소나의 언어로"그 시기에 거길 다녀온 사람들이 뭘 입었는지 보고 나면, 캐리어 반은 비울 수 있어."

④ 핵심 기능

✅ 구현됨 🔶 부분 구현 ⬜ 예정

1. 날씨 요약

✅ 구현됨

Open-Meteo 과거 10년 데이터로 여행 구간의 평균 최고·최저 기온·강수 확률·일교차를 요약 카드로 제공. 출발 D-14 이내엔 실제 예보를 병기.

★
기준점을 사용자로 옮김 (v1.3): 비교 기준 도시가 서울 하드코딩이었다. 제주 사는 사람에게는 무의미하고 서울 가는 사람에겐 동어반복이며, 인바운드 사용자에게는 아무 의미가 없다. 이제 IANA 타임존으로 거주 도시를 추정(25개 도시)해 비교하고, 목적지가 거주지와 사실상 같으면 비교 자체를 생략한다. 온도 단위도 로케일로 °C/°F를 자동 판정하고 토글로 바꿀 수 있다. 거주지·옷장 보유 여부를 묻지는 않는다 — 입력 단계를 늘리지 않고 감지로 해결한다.

2. 여행객 옷차림 레퍼런스 (킬러 기능)

✅ 구현됨

그 시기 그 목적지를 방문한 여행객들의 실제 사진 검색. 목적지 유형을 자동 판별해 도시형은 여행객/스트릿 스냅, 액티비티형(그랜드캐년 등)은 트레킹 등 해당 활동 복장을 수집.

★
실제 날씨를 검색에 반영 (v1.2 핵심 보강): 10년 평균(또는 예보) 기온으로 계산한 기온대를 의류 키워드로 변환해 모든 검색어에 주입한다. 예) 헬싱키 1월(−5~−1°) → winter freezing cold heavy coat puffer, 방콕 4월(27~35°) → hot humid summer linen shorts. 달력상 '월'만으로는 남반구·고산·사막에서 빗나가므로, "그 목적지가 실제로 얼마나 덥고 추운지"를 기준으로 옷을 찾는다.

소스: 핀터레스트(옷차림 콘텐츠 위주라 결과가 가장 깨끗함) 1순위 + 구글 이미지(부정 키워드·사진 전용 필터로 지도·호텔·음식 제거) + 인스타그램(해시태그·위치 탐색 링크 — API 제약으로 직접 수집 불가).

3. 날짜별 코디 추천

✅ 구현됨

날씨 × 여행객 경향 × 내 스타일 프로필 교차. 아이템 풀 조합 방식으로 같은 기온대라도 날마다 다른 코디를 제안. 일정 성격(관광/식사·격식/액티비티)을 날짜별로 선택하면 코디가 바뀐다 — 액티비티 날은 방풍·방수 아우터와 트레킹화로 교체, 격식 날은 스타일별 포인트 아이템 추가. 그날의 일교차·강수 확률도 코디 메모로 반영.

└ 내 스타일 프로필

🔶 부분 구현

사진 여러 장을 업로드하면 색감·톤(뉴트럴 비중·채도)을 클라이언트에서 분석해 4가지 스타일(미니멀/캐주얼/클래식/스트릿) 중 하나를 자동 추천하고 대표 팔레트를 표시. Phase 2에서 Claude 비전으로 실루엣·무드까지 분석 예정.

4. 여행 준비 리스트 (v1.3 재정의)

✅ 구현됨

v1.2의 '지참 리스트'는 옷 리스트였다. 페르소나의 실제 준비물 1순위는 가게 목록·현금·아이 여벌옷·등산화 상태·카메라 배터리였고 옷은 다섯 번째 줄이었다. 그래서 리스트를 여행 준비 전반으로 확장하고, 옷차림 추천은 그중 '의류' 섹션을 자동으로 채우는 엔진으로 위치를 바꿨다.

  • 자동 생성 준비물 — 해외/국내 여부에 따라 여권(유효기간 6개월)·항공권·해외 결제 카드·현지 통화·보험·멀티어댑터 또는 신분증·예약 확인. 여기에 충전기, 2박 이상이면 보조배터리, 상비약, 세면도구.
  • 날씨 조건부 — 강수 확률 35% 이상이면 접이식 우산, 평균 최고 26° 이상이면 자외선 차단제, 최저 5° 이하면 보온 이너, 일교차 10° 이상이면 얇은 겉옷.
  • 분류 7종 — 의류·신발·악세서리·서류·결제·전자기기·상비약·기타. 사용자 직접 추가 시 분류를 고를 수 있다(v1.2에선 전부 '기타'로 떨어졌다).
  • 편집 — 보유/사야 함 토글, ✎ 이름 수정(같은 이름은 전 날짜 일괄 반영), 직접 추가·삭제. 여러 날 쓰는 옷은 자동 병합되고 착용 일수가 표기된다.

5. 여행 목적 칩 (v1.3 신규)

✅ 구현됨

지형 3분류(도시형/자연·액티비티형/혼합형)로는 여행의 목적이 표현되지 않았다. 감성 기록 여행, 미식 여행, 저강도 숲길 산책(트레킹화 추천은 과했다), 한옥·온천·단풍 촬영이 전부 '도시형'으로 뭉쳤다. 상위 3유형은 유지하되 아래에 다중선택 목적 칩 13종을 두었다(한 여행에 2~3개 선택 상정).

목적 (그룹핑)

  • 도시형 — 미식 / 감성·기록 / 쇼핑 / 전시·문화 / 야경·나이트
  • 자연·액티비티형 — 트레킹·등산 / 숲길·산책 / 해변·물놀이 / 캠핑
  • 혼합·휴양형 — 온천·스파 / 리조트·호캉스 / 로컬 체험 / 격식·이벤트

실제 반영 방식

  • 신발·아우터를 덮어씀 — 해변·물놀이 → 샌들, 트레킹·등산 → 트레킹화 + 방풍
  • 준비물 추가 — 캠핑 → 경량 패딩·헤드랜턴, 미식 → 물티슈
  • 주의 문구 — 미식은 좌식 대응·냄새 배는 소재 회피 등

6. 성별 · 저장 리스트 · 내보내기 (v1.3 신규)

✅ 구현됨

동행 기능은 만들지 않았다. 앱은 1인 기준을 유지하되, 가족 여행은 기준을 바꿔 다시 검색하고 저장하는 방식으로 푼다.

  • 성별 입력(남/여/선택 안 함) — 추천 아이템 풀만 넓힌다. 나이대는 받지 않는다(스타일 프로필이 그 역할을 대신함).
  • 저장 리스트 — 검색 결과를 저장·불러오기·삭제. 아이 기준으로 한 번 더 검색해 따로 저장하면 가족 여행이 커버된다.
  • 마지막 결과 자동 보존 — 저장 버튼을 누르지 않아도 마지막 준비 리스트는 남는다. 날씨 응답까지 스냅샷하므로 복원 시 네트워크 요청이 없다.
  • 텍스트 복사 — 페르소나 10인 전원이 이미 시트·메모·카톡 같은 대체재를 쓰고 있었고, 한 명은 리스트를 자기 시트로 옮기려다 손으로 받아 적었다. 큰 기능 대신 복사 버튼 하나로 워크플로 밖으로 밀려나지 않게 했다.

7. 한국어 / English (v1.3 신규)

✅ 구현됨

인바운드 페르소나는 링크가 열려도 검색어(경주여행룩)와 결과가 한국어라 읽지 못했다. UI뿐 아니라 추천 아이템명·팁·목적까지 전부 번역하고, 레퍼런스 검색어와 인스타 해시태그도 언어를 따라가게 했다. 기본값은 브라우저 언어 자동 감지.

설계상 핵심은 상태에는 한국어를 저장하고 렌더 시점에만 번역하는 것이다. 저장한 리스트와 스냅샷이 특정 언어에 묶이지 않고, 언어를 바꿔도 재조회 없이 즉시 다시 그려진다.

8. 드레스코드 · 문화 팁

✅ 구현됨

도시별 큐레이션(20개 도시) + 국가 단위 폴백 + 실제 날씨 데이터 기반 체크포인트 자동 생성(비 확률·일교차·더위·추위에 맞춘 준비물) + 액티비티 준비물 안내로 3단계 구성. 종교시설 복장, 레스토랑 드레스코드, 돌길·냉방 등 현지 맥락 포함.

넣고 싶었지만 뺀 것

  • AI 자동 생성형 패킹 리스트 — 뻔한 결과물. 사용자가 확정한 계획에서 리스트가 도출되는 옷장 플래너로 대체.
  • 부족 아이템 쇼핑 제안 — 추천의 순수성 훼손 + 커머스 복잡도. '사야 할 옷' 입력·표시까지만, 구매 연결은 안 함.
  • 실시간 예보 중심 UI — 기존 날씨 앱과 중복.

⑤ 성공 기준

"좋아요"가 아니라 행동으로 관찰한다. 다음 두 가지가 관찰되면 성공:

  • 안 입고 돌아온 옷이 지난 여행보다 줄어든다. (여행 후 캐리어 리뷰 — 과잉 패킹의 직접 지표)
  • 추천 코디를 실제로 입은 날이 여행 일수의 절반 이상. (추천이 "참고"가 아니라 "결정"으로 쓰였다는 증거)

보조 관찰: 계획(D-30)·준비(D-7)·짐싸기(D-1) 세 시점에 다시 열어보는지, 옷장 플래너에서 날짜별 옷 배정을 실제로 완료하는지(계획 완성률).

⑥ 만들지 않을 것 (범위 밖)

  • 다중 사용자·계정 시스템 — 1차 타겟은 나 한 명. 개인 도구로 검증이 먼저.
  • AI 자동 패킹 리스트, 쇼핑·커머스 연계(구매·결제). 단, 사용자 주도 옷장 플래너와 도출 리스트는 범위 안(④-4).
  • 자체 스트릿 스냅 수집 파이프라인 — Phase 3 이후 검토.
  • SNS·커뮤니티 기능, 실시간 예보 앱 기능 전반.

⑦ 데이터 · API 설계

  • 날씨 (Open-Meteo · 구현됨): Geocoding(도시명→좌표), Historical Weather(10년 평균), Forecast(D-14 예보 병기). 무료·키 불필요.
  • 목적지 검색 재설계 (v1.3): v1.2의 한글→영문 폴백은 실패율이 높았다. 원인은 Open-Meteo(GeoNames)의 주 색인이 로마자라는 것 — language=ko는 결과 라벨만 번역할 뿐 한글로 검색되게 해주지 않는다. 그 결과 '서울'·'제주'·'경주'는 0건, '대구'·'전주'는 북한 지명이 올라왔다. 게다가 language 파라미터는 라벨뿐 아니라 매칭에도 영향을 준다(language=ko로 "New York"을 물으면 뉴욕시가 후보에 없다). 그래서 다음과 같이 바꿨다.
    • 원문 · 별칭사전 · 로마자 변환(개정 로마자 표기법 음절 분해)을 두 언어로 동시에 조회한 뒤 결과를 합쳐 순위를 매긴다
    • 인구 규모를 행정등급보다 우선 — 인구 7,864명의 York(영국식 PPLA2)가 인구 880만 뉴욕시를 이기고, 이름이 겹치는 벽지 지명이 광역시를 밀어내던 문제
    • 북한(KP) 결과 제외, 좌표 기준 중복 제거, 이전 요청 취소(AbortController)로 응답 경합 해소
    • 해외 도시 별칭 80여 개 추가 — 음절 자동 변환만으로는 '교토'가 Kyoto가 아니라 발음이 비슷한 툰드라 마을로 잡힌다
  • 여행객 이미지 (단계적): Phase 1은 검색 링크 방식 — 핀터레스트/구글/인스타 링크에 목적지 유형 + 실제 기온대 키워드 결합. 구글은 부정 키워드·사진 전용 필터로 정제. Phase 2에서 Claude 비전 필터링 후 앱 내 인라인 표시.
  • AI 레이어 (Claude API): (0) 유형 판별 — 현재 규칙 기반, Phase 2 Claude 분류. (1) 스타일 — 색감 휴리스틱 → Claude 비전. (2) 코디 — 규칙 기반 풀 → Claude 생성. (3) 팁 — 큐레이션+날씨 규칙 → 웹 검색 요약.

⑧ 시스템 플로우

[도시·날짜·유형·스타일 입력]
      │
      ▼
[Geocoding(한글→영문 폴백)] → [Historical + (D-14 예보)] → 10년 평균 요약 + 서울 비교
      │
      ├─→ [기온대 키워드 주입] → [핀터레스트/구글(필터)/인스타] → 여행객 옷차림 레퍼런스
      │
      ├─→ [사진 업로드 → 색감 분석] → 스타일 프로필(미니멀/캐주얼/클래식/스트릿)
      │
      ▼
[날씨 × 기온대 × 스타일 × 일정성격] → 날짜별 코디 + 편집형 옷장 플래너 → 실시간 지참 리스트
      │
      ▼
[도시/국가 팁 + 날씨 기반 체크포인트] → 드레스코드·문화 팁

⑨ 화면 구성 (IA)

v1.3 — 3개 뷰로 분리. v1.2는 입력·결과·저장이 한 페이지에 쌓여 모바일 스크롤이 지나치게 길었다. 하단 내비게이션 기반 3분할로 바꾸고, 검색 뷰 밖에서는 히어로 헤더를 한 줄 바로 축소했다(세로 약 130px 회수).

  • 🔍 검색 — 여행지(자동완성)·출발/도착일·목적지 유형(자동 판별)·여행 목적 칩·성별·스타일. 헤더에 언어(한국어/EN)·단위(°C/°F) 토글.
  • 🧳 준비 리스트 — 결과 탭 4개: 날씨(요약 카드 + 거주지 비교) / 여행객 룩(기온대 반영 검색 링크) / 여행 준비(날짜별 코디 + 여행 준비 리스트 + 복사·저장) / 팁.
  • 🔖 저장 — 저장한 여행 목록(불러오기·삭제), 미확인 개수 뱃지.

검색이 끝나면 준비 리스트 뷰로 자동 이동하고, 오류는 오류 문구가 있는 검색 뷰로 되돌린다.

⑩ 로드맵

Phase 1 — 프로토타입

✅ 완료

입력 → 날씨 요약(서울 비교·D-14 예보) → 기온대 반영 레퍼런스 → 사진 색감 스타일 분석 → 규칙 기반 날짜별 코디 → 편집형 옷장 플래너·실시간 지참 리스트 → 도시/날씨 기반 팁. 핵심 경험 유용성 본인 검증 충족.

Phase 1.5 — 페르소나 검증 반영 (v1.3)

✅ 완료

가상 페르소나 10인 패널 → 제품 가정의 문제 7가지 도출 → 여행 준비 앱으로 포지션 전환, 기준점 자동 판정, 목적 칩, 성별·저장·복사, 한/영 지원, 검색 정확도 재설계, 화면 3분할, Vercel 프로덕션 배포. 남은 항목은 날짜 후보 비교 뷰(주차별 기온 스트립).

Phase 2 — 개인 도구 완성

🔶 진행 중

Claude 비전 스타일 프로필, 이미지 검색 결과 AI 필터링 및 앱 내 인라인 표시, 스타일 프로필 저장, 유형·코디·팁의 Claude 생성 전환, 3개 시점(A/B/C) 화면 분화.

Phase 3 — 확장 검토

⬜ 예정

실사용 데이터를 근거로 외부 공개 여부 판단. 자체 이미지 데이터 파이프라인, 패킹 리스트·쇼핑 연계 등 보류 기능 재검토.

⑪ 리스크와 열린 질문

  • 이미지 품질·권리: 검색 결과는 시기·품질이 들쭉날쭉하고 저작권 이슈가 있다. 개인 도구는 링크 표시 방식으로 회피(외부 공개 시 재검토). 인스타는 탐색 링크만, 외부 사이트 로그인은 앱이 관여하지 않는다.
  • 스타일 분석의 주관성: Phase 1 색감 분석은 실루엣·무드를 못 본다. 언제든 수정 가능하게 했고 Phase 2 Claude 비전으로 정교화.
  • 기후 평균의 한계: 이상기후 시 평균이 빗나갈 수 있어 D-14 이내엔 예보 병기. 현재 기간 평균 기온으로 검색 — 변동이 큰 경우 날짜별 분리 검색 검토.
