# PRD — 여행 옷차림 추천 서비스 (가칭: TripFit / WeatherClothe)

과제 1 · PRD 기획 및 구현 | 작성: Sylvia | 2026-07-25 | v1.2 (프로토타입 구현 반영)

> **v1.2 변경 요약** — Phase 1 프로토타입을 실제 동작하는 웹앱으로 구현하면서 확정·보강된 내용을 반영. ① 여행객 레퍼런스 검색에 **실제 기온대(날씨 데이터)를 키워드로 주입**(핵심 기능 정상화), ② '내 코디'와 '옷장 플래너'를 **하나의 화면으로 통합**하고 칩 편집·직접 입력 추가, ③ 사진 업로드 기반 색감 스타일 분석 구현, ④ 목적지·문화 팁 데이터 대폭 확장, ⑤ 현대카드 DIVE 스타일 디자인 시스템 적용. 자세한 구현 현황은 §12 참조.

---

## ① 문제 정의

**누가·언제·어떤 상황에서:** 해외여행을 앞둔 여행자가, 여행 확정 후부터 짐 싸기 직전까지, 목적지의 그 시기 날씨와 적절한 옷차림을 판단하지 못하고 있다. 일기예보는 출발 직전에야 유효하고, "최고 14도"라는 숫자만으로는 무엇을 입을지 감이 오지 않는다.

**지금은 어떻게 버티고 있는가(대체재):** "3월 파리 옷차림" 블로그 검색 — 몇 년 전 글, 광고성 콘텐츠, 글마다 다른 결론. 결과적으로 불안해서 옷을 과잉으로 싸간다.

## ② 주요 페르소나

**상황으로 정의:** 스타일 기준이 뚜렷한 30대 디자이너. 여행 옷차림도 취향에 맞아야 하지만, 목적지 날씨에 대한 확신이 없어 "혹시 몰라" 옷을 계속 추가하다가 캐리어가 넘친다. 도시 여행과 그랜드캐년 같은 액티비티 여행을 모두 다닌다.

**실제로 뱉은 문장:**
> "결국 옷을 너무 많이 싸가서 반은 안 입었어."

## ③ 주요 가치 · 소구 방식

**이 프로덕트가 지키는 것 한 줄:** 추측이 아니라 근거(10년 기후 데이터 + 같은 시기 여행객들의 실제 옷차림)로 옷을 결정하게 한다.

**페르소나의 언어로 번역한 한 문장:** "그 시기에 거길 다녀온 사람들이 뭘 입었는지 보고 나면, 캐리어 반은 비울 수 있어."

## ④ 핵심 기능

소구 방식(근거 기반 결정)을 지탱하는 기능만 남긴다. *(✅ 구현됨 / 🔶 부분 구현 / ⬜ 예정)*

1. **날씨 요약 ✅** — Open-Meteo 과거 10년 데이터로 여행 구간의 평균 최고·최저 기온·강수 확률·일교차를 요약 카드로 제공. **기준 도시(서울) 비교 번역**("서울의 같은 시기보다 평균 최고기온이 약 4도 낮아요")을 함께 표시. 출발 D-14 이내엔 실제 예보를 병기.

2. **여행객 옷차림 레퍼런스 (킬러 기능) ✅** — 그 시기 그 목적지를 방문한 여행객들의 실제 사진 검색. 목적지 유형을 자동 판별해 도시형은 여행객/스트릿 스냅, 액티비티형(그랜드캐년 등)은 트레킹 등 해당 활동 복장 사진을 수집.
   - **★ 실제 날씨를 검색에 반영(v1.2 핵심 보강):** 10년 평균(또는 예보) 기온으로 계산한 **기온대를 의류 키워드로 변환**해 모든 검색어에 주입한다. 예) 헬싱키 1월(-5~-1°) → `winter freezing cold heavy coat puffer`, 방콕 4월(27~35°) → `hot humid summer linen shorts`. 달력상 '월'만으로는 남반구·고산·사막에서 빗나가므로, "그 목적지가 실제로 얼마나 덥고 추운지"를 기준으로 옷을 찾는다.
   - **소스:** 핀터레스트(옷차림 콘텐츠 위주로 결과가 가장 깨끗함) 1순위 + 구글 이미지 검색(부정 키워드·사진 전용 필터로 지도·호텔·음식 제거) + 인스타그램(해시태그·위치 탐색 링크 — API 제약으로 직접 수집 불가, 탐색 링크만 제공).

3. **날짜별 코디 추천 ✅** — 날씨 × 여행객 경향 × 내 스타일 프로필 교차. **아이템 풀 조합 방식**으로 같은 기온대라도 날마다 다른 코디를 제안(고정 문장 반복 방지). 일정 성격(관광/식사·격식/액티비티)을 날짜별로 선택하면 코디가 바뀐다 — 액티비티 날은 방풍·방수 아우터와 트레킹화로 교체, 격식 날은 스타일별 포인트 아이템 추가. 그날의 일교차·강수 확률도 코디 메모로 반영.
   - **내 스타일 프로필 🔶:** 여행/일상 사진 여러 장을 업로드하면 **색감·톤(뉴트럴 비중·채도)을 클라이언트에서 분석**해 4가지 스타일(미니멀/캐주얼/클래식/스트릿) 중 하나를 자동 추천하고 대표 팔레트를 표시. (Phase 1은 색감 휴리스틱, Phase 2에서 Claude 비전으로 실루엣·무드까지 분석 예정.)

4. **옷장 플래너 & 실시간 지참 리스트 ✅** — **'내 코디' 화면에 통합.** 날짜별 추천 코디의 각 아이템이 칩으로 표시되고, 사용자가:
   - **보유 / 사야 함**을 칩 클릭으로 전환,
   - **✎ 로 칩 이름을 내 옷에 맞게 수정**(예: '와이드 린넨 팬츠' → '베이지 와이드 린넨 팬츠') — 같은 이름 아이템은 모든 날짜에 함께 반영돼 병합 카운팅 유지,
   - **보유한 아이템을 직접 입력해 추가**.
   여러 날짜에 배정된 같은 옷은 자동 병합되어, 최종 지참 리스트(의류·신발·악세서리·기타로 분류, '사야 할 옷' 배지 표시, 착용 일수 표기)가 실시간으로 갱신된다. 성공 기준 1번(과잉 패킹 감소)을 직접 달성하는 기능.

5. **드레스코드·문화 팁 ✅** — 도시별 큐레이션(20개 도시) + **국가 단위 폴백** + **실제 날씨 데이터 기반 체크포인트 자동 생성**(비 확률·일교차·더위·추위에 맞춘 준비물) + 액티비티형 준비물 안내로 3단계 구성. 종교시설 복장, 레스토랑 드레스코드, 돌길·냉방 등 현지 맥락 포함.

**넣고 싶었지만 뺀 것:** AI 자동 생성형 패킹 리스트(뻔한 결과물 — 대신 사용자가 날짜별로 확정한 계획에서 리스트가 *도출*되는 옷장 플래너로 대체), 부족 아이템 쇼핑 제안(추천의 순수성 훼손 + 커머스 복잡도 — '사야 할 옷' 입력·표시까지만 지원하고 구매 연결은 하지 않음), 실시간 예보 중심 UI(기존 날씨 앱과 중복).

## ⑤ 성공 기준

"좋아요"가 아니라 행동으로 관찰한다. 다음 두 가지가 관찰되면 성공:

1. **안 입고 돌아온 옷이 지난 여행보다 줄어든다.** (여행 후 캐리어 리뷰로 측정 — 과잉 패킹 문제의 직접 지표)
2. **추천 코디를 실제로 입은 날이 여행 일수의 절반 이상.** (추천이 "참고"가 아니라 "결정"으로 쓰였다는 증거)

보조 관찰: 한 여행 주기에서 계획(D-30)·준비(D-7)·짐싸기(D-1) 세 시점에 다시 열어보는지. 옷장 플래너에서 날짜별 옷 배정을 실제로 완료하는지(계획 완성률).

## ⑥ 만들지 않을 것 (이번 범위 밖)

- 다중 사용자·계정 시스템 — 1차 타겟은 나 한 명. 개인 도구로 검증이 먼저.
- AI 자동 생성형 패킹 리스트, 쇼핑·커머스 연계(구매 링크·결제) — ④에서 뺀 이유와 동일. 단, 사용자 주도 옷장 플래너와 그로부터 도출되는 지참 리스트는 범위 안(④-4).
- 자체 스트릿 스냅 수집 파이프라인(크리에이터 제휴, 유저 제보) — Phase 3 이후 검토. 지금은 이미지 검색 + AI 필터링으로 충분.
- SNS·커뮤니티 기능, 실시간 예보 앱 기능 전반.

## ⑦ 데이터·API 설계

- **날씨 (Open-Meteo, 확정·구현됨):** Geocoding API(도시명→좌표, 한글 검색 + 실패 시 영문 별칭·영어 재검색 폴백), Historical Weather API(10년 평균), Forecast API(D-14 이내 예보 병기). 무료·API 키 불필요.
- **여행객 옷차림 이미지 (단계적):** Phase 1은 **검색 링크 방식** — 핀터레스트/구글 이미지/인스타그램 탐색 링크에 목적지 유형 + **실제 기온대 키워드**를 결합해 생성. 구글은 부정 키워드(`-map -hotel -food …`)와 사진 전용 필터로 정제. Phase 2에서 Claude 비전으로 이미지 실물 필터링 후 앱 내 인라인 표시 예정.
- **AI 레이어 (Claude API):** (0) 목적지 유형 판별 — 현재 프로토타입은 별칭/키워드 사전 기반 규칙으로 구현, Phase 2에서 Claude 분류로 고도화. (1) 스타일 프로필 — Phase 1 색감 휴리스틱 → Phase 2 Claude 비전. (2) 코디 추천 — Phase 1 규칙 기반 아이템 풀 → Phase 2 Claude 생성. (3) 문화 팁 — Phase 1 큐레이션+날씨 규칙 → Phase 2 웹 검색 연동 요약.

## ⑨ 화면 구성 (IA)

**입력 카드:** 여행지(자동완성)·출발/도착일·목적지 유형(자동 판별)·스타일(사진 업로드 분석 또는 선택). **결과 탭 4개:**
- **날씨** — 기후 요약 카드(대형 숫자 그리드) + 서울 비교.
- **여행객 룩** — 기온대 반영 검색 링크(핀터레스트/구글/인스타) + AI 코멘트.
- **내 코디** — 날짜별 추천 코디 + 편집형 옷장 플래너(칩 보유/사야함·이름 수정·직접 추가) + 하단 실시간 지참 리스트.
- **팁** — 도시/국가 드레스코드 + 이번 여행 날씨 체크포인트 + 액티비티 준비물.

## ⑩ 로드맵

- **Phase 1 — 프로토타입 ✅ (완료):** 도시·날짜·유형·스타일 입력 → Open-Meteo 날씨 요약(서울 비교·D-14 예보) → 기온대 반영 레퍼런스 검색 링크 → 사진 색감 기반 스타일 분석 → 규칙 기반 날짜별 코디 → 편집형 옷장 플래너·실시간 지참 리스트 → 도시/날씨 기반 팁. 목표(핵심 경험이 실제로 유용한지 본인 검증) 충족.
- **Phase 2 — 개인 도구 완성 🔶 (진행 중):** Claude 비전 스타일 프로필, 이미지 검색 결과 AI 필터링 및 앱 내 인라인 표시, 스타일 프로필 저장, 목적지 유형·코디·팁의 Claude 생성 전환, 3개 시점(A/B/C) 화면 분화.
- **Phase 3 — 확장 검토 ⬜:** 실사용 데이터를 근거로 외부 공개 여부 판단. 자체 이미지 데이터 파이프라인, 패킹 리스트·쇼핑 연계 등 보류 기능 재검토.

## ⑪ 리스크와 열린 질문

- **현지 옷차림 이미지의 품질·권리:** 검색 결과는 시기·품질이 들쭉날쭉하고 저작권·퍼블리시티 이슈가 있다. 개인 도구 단계는 **검색 결과 링크 표시 방식으로 회피**(외부 공개 시 반드시 재검토). 인스타는 API 제약으로 탐색 링크만 제공. 외부 사이트 로그인(핀터레스트 등)은 앱이 관여하지 않는다.
- **스타일 분석의 주관성:** Phase 1 색감 분석은 실루엣·무드를 못 본다. 사용자가 언제든 드롭다운으로 수정 가능하게 했고, Phase 2 Claude 비전으로 정교화.
- **기후 평균의 한계:** 이상기후 시 10년 평균이 빗나갈 수 있어 D-14 이내에는 실제 예보를 항상 병기. 현재는 여행 기간 평균 기온으로 레퍼런스를 검색 — 기간 내 기온 변동이 큰 경우 날짜별 분리 검색을 향후 검토.
