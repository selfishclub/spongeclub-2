## 📝 과제 1. PRD — 사업자용 AI 손익관리 앱

> `tags: [PRD, 손익자동화, 스폰지클럽]` · 작성일 2026-07-25 · v1.0

### 1. 한 줄 정의
**"매출은 아는데 영업이익은 모르는 사업자를 위한, 클릭 한 번 손익관리 앱"**

### 2. 문제 정의
1. 매출은 늘어나는데 통장 잔고는 그대로 — *실제로 남는 돈*을 모른 채 사업한다
2. 손익 마감이 고역 — 홈택스·카드·통장·판매채널 엑셀을 손으로 모아 **하루 이상**
3. 만들어도 못 믿는다 — 숫자는 에러 없이 **조용히** 틀린다 (이중집계, 형식 함정, 수식 미계산)

### 3. 페르소나
| 페르소나 | 상황 | 통증 | 소구 포인트 |
|---|---|---|---|
| ① 이커머스 대표 (40대, 비개발자) | 판매채널 4~5개, 직원 소수 | 마감에 하루+, 영업이익률을 모름 | "클릭 한 번, 실제 남는 돈" |
| ② 사이드잡 셀러 (30대) | 스마트스토어 1인 운영 | 매출총이익·영업이익 개념 자체가 없음 | 개념 교육 + 자동 계산 |
| ③ 1인 재무담당 | 소기업 경리 겸직 | 매달 같은 취합 반복 | 수집 자동화로 반복 제거 |

### 4. 주요 가치 (Value Proposition)
1. **자동 수집** — 세금계산서·통장·카드를 조회 API(바로빌)로 매일 수집. 운영비 월 약 4만 원
2. **진짜 남는 돈** — 원가·플랫폼 수수료·광고비·택배비·물류비 등 판관비 16종 자동 분류
3. **믿을 수 있는 숫자** — 매달 고정 기준값 4종과 원 단위 자동 대사. "AI는 조용히 틀린다"를 시스템으로 방어
4. **판단까지** — 배당 여력, 연말 예상, 카드 소비 연환산 등 경영 판단 패널

### 5. 소구 방식
- **훅**: "매출은 늘어나는데, 통장 잔고는 왜 그대로일까요?"
- **서사**: 손익 정리는 대표의 의무 — 매출총이익과 영업이익의 매월 비교·분석은 대표가 반드시 해야 할 일. 개념부터 잡아주고, 도구로 끝낸다
- **증명**: 라이브 데모 + 공개 데모 링크 (가상 데이터)

### 6. 성공 지표 (KPI)
| 지표 | 목표 | 실측 |
|---|---|---|
| 월 마감 소요 시간 | 1시간 이내 | **30분** (기존 하루+) |
| 숫자 신뢰도 | 기준값 4종 대사 100% 통과 | 통과 (원 단위 일치) |
| 재계산 오류 | 0건 | 0건 (수식 1,902개) |
| 운영 비용 | 월 5만 원 이내 | 약 4만 원 (API 정액) |
| 사용 빈도 | 대표가 주 1회 이상 대시보드 확인 | 측정 예정 |

### 7. 기능 요구사항 (우선순위)
| 우선순위 | 기능 | 상태 |
|---|---|---|
| P0 | 소스 자동 수집 — 세금계산서·통장·카드 API + 판매·재고 파일 | ✅ 완료 |
| P0 | 원장 정규화 — 소스 6종 → 매출·항목 원장, 중복 제거 | ✅ 완료 |
| P0 | 판관비 16종 자동 분류 · 채널별 마진 계산 | ✅ 완료 |
| P0 | 자동 검증 — 기준값 4종 원 단위 대사, 불일치 시 중단 | ✅ 완료 |
| P1 | 대시보드 — KPI·추이·원장 뷰·드릴다운·카드 소비 분석 | ✅ 완료 |
| P1 | 경영 판단 패널 — 배당 여력·연말 예상·용역비 토글 | ✅ 완료 |
| P1 | 모바일/웹 접근 — 로그인 게이트 + 클라우드 스냅샷 | ✅ 완료 |
| P2 | 판매채널 정산 엑셀 직접 업로드 | 백로그 (페르소나 ①) |
| P2 | "이번 달 써도 되는 돈" 카드 | 백로그 (페르소나 ②) |
| P2 | 집계 기준(VAT별도·귀속월) 화면 명시 | 백로그 (페르소나 ③) |

### 8. 범위 제외 (Out of Scope)
- **세무 신고** — 경영 판단용이지 신고 자료가 아니다 (세무사 영역 침범 안 함)
- **품목별 수익성 분석** — 판매 원본에 품목 데이터가 없어 선행 데이터 확보 전엔 불가
- **다중 사용자·권한 관리** — 1인(대표) 사용 전제

### 9. 리스크와 가정
| 리스크 | 대응 |
|---|---|
| 조회 API 포인트 소진 시 수집 중단 | 선불 충전 잔액 관리 (월 4만 원 소진 기준) |
| 홈택스·소스 파일 형식 변경 | 파일 시그니처 판별 + 대사 실패 시 즉시 감지 |
| 에러 없이 조용히 틀리는 오류 | 기준값 4종 자동 대사가 최후 방어선 |
| 개인정보(급여 등) 유출 | 해당 파일은 수집·커밋 제외, 로컬 전용 |

### 10. 구현 결과
- 파이프라인: 수집(API) → 원장 정규화 → 재계산 → 자동 검증 → 대시보드(웹·모바일)
- 스택: Claude Code, Python, LibreOffice(수식 재계산), Chart.js, Vercel + Supabase
- 지표: 43개월 손익 원장 · 수식 1,902개 · 재계산 오류 0 · 마감 하루+ → **30분** · 누락 0건
- 🔗 데모: https://pnl-automation-beta.vercel.app/demo.html (거래처·금액은 가상)

## 🗣 과제 2. 유저 피드백 받기

### 실제 유저 피드백 — 미진행
이번 주차에는 실제 유저 인터뷰를 진행하지 못했다.
대신 **가상 페르소나 3명 시뮬레이션**으로 대체하고, 실제 인터뷰용 질문지만 준비해 둔다.

**질문지 (추후 실제 인터뷰용)**
1. 첫 화면 3초 — 무슨 앱인지 바로 이해됐나요?
2. 본인 사업이라면 어떤 숫자부터 보고 싶으세요?
3. "실제 남는 돈"이 믿기던가요? 안 믿긴다면 어디서?
4. 매달 쓴다면 얼마까지 낼 수 있을까요?
5. 없어서 아쉬운 기능 하나만 꼽는다면?

### 가상 페르소나 피드백 (AI 시뮬레이션)

**① 스마트스토어 셀러 (32, 사이드잡)**
- 좋았던 점: "매출총이익 vs 영업이익을 여기서 처음 구분하게 됐다. 카드 소비 연환산이 제일 뜨끔했다."
- 아쉬운 점: "스마트스토어·쿠팡 정산 엑셀을 그대로 던지면 알아서 읽어주면 좋겠다. 세금계산서가 없는 매출이 많다."
- 한 마디: "월 1만 원이면 쓴다. 4만 원이면 고민."

**② 오프라인 카페 사장 (51)**
- 좋았던 점: "통장 입출금이 자동으로 들어오는 게 제일 부럽다. 장부랑 잔고가 안 맞는 게 평생 스트레스였다."
- 아쉬운 점: "포스기 매출 연동이 없으면 나 같은 오프라인 장사는 반쪽이다."
- 한 마디: "숫자보다 '이번 달 얼마 써도 되는지'를 알려주면 최고."

**③ 세무사 (45)**
- 좋았던 점: "기준값 대사로 검증한다는 발상이 실무적이다. 대부분 자동화는 수집만 하고 검증을 안 한다."
- 아쉬운 점: "부가세 별도/포함 기준과 귀속월 처리 기준을 화면에 명시해야 신뢰가 산다. 세무 신고용이 아니라 '경영 판단용'임을 분명히 하라."
- 한 마디: "사장님들이 이걸 들고 상담 오면 대화가 빨라지겠다."

### 반영 백로그 (피드백 → 다음 액션)
- [ ] 판매채널 정산 엑셀 직접 업로드 지원 (①)
- [ ] "이번 달 써도 되는 돈" 카드 추가 검토 (②)
- [ ] 화면에 집계 기준(VAT별도·귀속월) 명시 (③)
- [ ] 실제 유저 인터뷰 2명 (질문지 준비 완료, 다음 주차 진행)

## 💡 인사이트
- **PRD를 쓰면서 "무엇을 안 할지(Out of Scope)"가 오히려 제품을 선명하게 만들었다.** 세무 신고·품목별 분석을 과감히 빼니, "경영 판단용 손익"이라는 한 문장이 남았다.
- **가상 페르소나 시뮬레이션도 충분히 날카로운 피드백을 준다.** 특히 세무사 페르소나의 "부가세 기준·귀속월을 화면에 명시하라"는 지적은 신뢰 설계의 핵심을 짚었고, 바로 백로그로 옮겼다.
- **다음 액션이 분명해졌다.** 페르소나별 통증이 그대로 P2 백로그(정산 엑셀 업로드 · "써도 되는 돈" 카드 · 집계 기준 명시)가 됐고, 실제 인터뷰 질문지까지 준비돼 다음 주차로 이어진다.
