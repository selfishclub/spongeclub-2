## 결과물

실제 배포: https://top10-five-ruby.vercel.app

**1. 디자인**
- 처음엔 다크 톤의 "필름 카운트다운" 컨셉(앰버/블랙, 회전하는 링 배지 등)으로 만들었다가 반려당하고, 토스 스타일의 밝고 심플한 UI로 전면 재설계
- 순위 배지, 포스터, 제목이 한 줄에 깔끔하게 보이는 리스트형 레이아웃으로 정착

**2. 리스트 편집 기능**
- 항목 삭제, 위/아래 한 칸씩 이동 버튼
- dnd-kit 라이브러리로 드래그앤드롭 순서 변경(PC 마우스·모바일 터치 둘 다 지원, 키보드 접근성도 유지)

**3. 검색 기능 개선**
- TMDB 검색 API가 띄어쓰기 없는 한글 검색어를 못 찾는 문제 발견(예: "잘알지도못하면서" 검색 시 0건) → 첫 글자부터 점점 늘려가며 재검색하는 폴백 로직 구현
- 감독 이름으로 검색하면 그 감독의 필모그래피 전체가 나오도록 개선(TMDB 인물 검색 + 크레딧 API 연동, 홍상수 검색 시 44편 확인)
- 연도 필터를 서로 겹치지 않는 구간(2020년 이후/2010년 이후/2000년 이후/1999년 이전)으로 재설계
- 인기 영화 추천 기능에 로딩 상태 표시 추가, 지역·연도 조합별로 더 많은 후보가 나오도록 개선

**4. 공유 카드 이미지**
- `next/og`로 인스타 스토리 비율(9:16)의 카드 이미지를 서버에서 직접 생성
- 포스터 10장을 3·3·4 그리드로 배치, 순위 번호와 영화 제목을 포스터 밑에 캡션으로 표시(제목이 길면 글자 크기를 줄여 한 줄에 맞춤)
- 장르 취향 태그, "나도 만들어보기" CTA + 실제 접속 도메인을 이미지 안에 표시
- 카드에 표시할 이름을 직접 입력할 수 있는 선택 필드(카카오 닉네임 자동 연동 대신 프라이버시를 고려해 수동 입력 방식 채택)

**5. 공유·초대 플로우**
- 버튼명을 "공유하기"에서 "텐픽 초대장 보내기"로 변경 — 단순 링크 공유가 아니라 "네 인생 영화 Top10은 뭐야?"라고 친구에게 물어보는 행위라는 관점을 반영
- 링크 복사 버튼과 OS 공유 시트(카카오톡/문자 등) 둘 다 지원
- 카카오 로그인, 로그인 없이도 볼 수 있는 공개 공유 페이지, 찜하기(로그인 필요) 기능

**6. 브랜딩 & 배포**
- 서비스명을 텐픽(TenPick)으로 확정, "10PICK" 워드마크 적용
- GitHub 저장소 연결, Vercel 배포, 카카오 로그인 리다이렉트 및 Supabase 인증 설정까지 완료

## 삽질 과정

- **디자인 반려**: 다크 "필름 카운트다운" 컨셉을 여러 파일에 걸쳐 구현했는데, 실사용성이 떨어진다는 피드백을 받고 전부 갈아엎었다. 이후로는 코드부터 짜지 않고 토스 스타일 대안 3~4개를 먼저 만들어 보여주고 컨펌받은 뒤에 개발하는 방식으로 작업 순서를 바꿨다.
- **원인 불명의 로컬 빌드 실패**: 로컬 개발 서버가 계속 안 뜨거나 빌드가 실패했다. 처음엔 네트워크 문제로 의심해서 IPv4 우선 DNS 설정, 텔레메트리 비활성화 등 여러 우회를 시도했지만 다 실패. 알고 보니 Windows Defender가 Next.js 빌드 캐시 파일(`.next/trace`)을 잠그고 있던 것이었다.
- **진짜 원인은 따로 있었음**: 빌드 문제를 우회하고 나니, Supabase 클라이언트가 내부적으로 Realtime 기능용 WebSocket을 요구하는데 Node 20 환경엔 기본 WebSocket이 없어서 서버 사이드에서 500 에러가 나고 있었다. 처음엔 `--experimental-websocket` 실행 플래그로 임시 봉합했다가, 배포 환경에서도 안정적으로 동작하도록 `ws` 패키지를 정식 transport로 연결하는 방식으로 다시 고쳤다.
- **Vercel 첫 배포 실패**: 로컬 전용으로 걸어뒀던 `distDir` 설정이 코드에 남아있어서, Vercel이 빌드 결과물을 엉뚱한 폴더에서 찾다가 배포가 실패했다. 설정을 제거하고 재배포해서 해결.
- **배포 후 발견한 치명적 버그**: 친구에게 공유 링크를 보냈는데, 클릭하니 서버 에러 화면만 떴다. 원인을 추적해보니, 드래그앤드롭 기능을 추가하면서 리스트 컴포넌트가 클라이언트 컴포넌트로 바뀌었는데, 공유 페이지(서버 컴포넌트)에서는 여전히 그 컴포넌트에 "찜하기 버튼을 그리는 함수"를 직접 넘기고 있었다. Next.js는 서버 컴포넌트가 클라이언트 컴포넌트에 함수를 넘기는 걸 허용하지 않는데(직렬화가 안 되기 때문), 이게 사실 예전에 한 번 고쳤던 문제를 기능 추가 과정에서 다시 만든 것이었다. 자동화 테스트(vitest/jsdom)로는 이런 종류의 에러를 절대 잡을 수 없고, 실제로 배포한 뒤 링크를 클릭해봐야만 드러난다는 것도 이번에 알게 됐다.
- **카드 이미지 텍스트 가독성 반복 수정**: 처음엔 포스터 위에 순위 숫자를 겹쳐 표시했는데 잘 안 보인다는 피드백 → 포스터 아래 캡션으로 분리. 영화 제목도 안 보인다는 피드백 → 제목을 추가했는데 폭을 넘으면 말줄임표로 잘렸다가, "줄임말 대신 글자 크기를 줄여서라도 한 줄에 다 보이게 해달라"는 피드백을 받고 한글/영문 글자 폭을 직접 추정하는 로직을 짜서 자동으로 폰트 크기를 줄이도록 구현했다(카드 이미지 생성 엔진이 브라우저처럼 실제 텍스트 폭을 측정해주지 않아서 직접 계산해야 했다).
- **다운로드 버튼 반응 없음**: 카드 이미지 저장 버튼이 원래 단순 링크였는데, 이미지 생성에 4초 가까이 걸리는 동안 아무 표시가 없어 사용자가 답답해했다. fetch로 이미지를 받아온 뒤 다운로드하는 방식으로 바꾸고 "이미지 만드는 중…" 로딩 문구를 추가했다.

## 인사이트

로컬에서 테스트를 다 통과해도 실제 배포 환경(프로덕션 Node 버전, 실제 도메인, 실사용자의 클릭)에서만 드러나는 문제가 따로 있다는 걸 몸으로 배웠다. 특히 서버 컴포넌트와 클라이언트 컴포넌트의 경계 문제처럼 자동화 테스트로는 원천적으로 잡히지 않는 버그가 있다는 게 인상 깊었고, 그만큼 실제 배포 후 직접 써보는 검증 단계가 필수라는 걸 다시 확인했다.

## 유저 피드백 (가상)

**유저 1**: 링크 받고 들어가봤는데 포스터 쫙 뜨니까 취향 바로 보여서 재밌었음! 근데 찜하기 눌렀더니 갑자기 로그인 화면으로 튕겨서 좀 당황했어 ㅋㅋ 찜하려면 로그인해야 한다고 미리 알려주면 좋을 듯.

**유저 2**: 카드 이미지 인스타에 올렸더니 반응 좋았어! 근데 순위 바꾸는 거 처음엔 어떻게 하는지 몰랐고, 다 채우면 이미지 카드 생긴다는 걸 미리 알았으면 처음부터 더 열심히 골랐을 듯. 완성 전에도 살짝 귀띔해주면 좋겠음.
