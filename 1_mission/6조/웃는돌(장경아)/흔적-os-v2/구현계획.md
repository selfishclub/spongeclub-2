## P0 — 전환 브리핑 (지금 구현됨 ✅)

**범위:** 전환 1개 · 하루 2터치 · AI 판단 없음 · 버튼 없음

```
🌙 21:30  [저녁 승인]  후보 3개 → 숫자 하나 답장 → 내일의 '하나' 확정
                       무응답이면 1번 자동 (아침에 그렇다고 밝힘)
🟢 09:00  [아침 배달]  확정된 하나를 되돌려줌. 읽으면 끝.
```

**구현물:** [`p0-전환브리핑/`](./p0-전환브리핑/)

| 파일 | 역할 |
|---|---|
| `api/cron-evening.js` | 저녁 승인 요청 발송 |
| `api/cron-morning.js` | 아침 브리핑 배달 |
| `api/telegram.js` | 숫자 답장(승인) · `완료` 처리 · 기존 캡처 |
| `lib/store.js` | Supabase 어댑터 — **스키마 다르면 이 파일만 수정** |
| `lib/brief.js` | 문안 생성 + KST 날짜 계산 |
| `lib/telegram.js` | 발송 helper |
| `schema.sql` | `daily_focus` 테이블 |
| `test/dry-run.js` | **배포 전 모킹 테스트** (2주차 방식 계승) |

**설계 결정 (근거는 PRD §4)**
- 후보 선정은 **`가장 오래 열린 순`** — 규칙 기반. **AI를 안 쓴다** (P10)
- 아침 메시지에 **버튼이 없다** (P9)
- 후보가 없으면 **아무것도 안 보낸다** (P7)
- 자동 선택이면 **"제가 골랐어요"라고 밝힌다** — 근거 없는 확신을 주지 않는다

**완료 기준 (DoD)**
- [ ] `node test/dry-run.js` 전부 PASS
- [ ] 실제 배포 후 저녁·아침 메시지가 **7일 연속** 도착
- [ ] 저녁 승인 **주 4일 이상**
- [ ] 아침에 고른 하나를 끝낸 날 **주 3일 이상**
- [ ] 무시율 30% 이하

## P1 — 답장이 곧 캡처

**범위:** 자연어 답장을 흔적으로 흡수. 별도 캡처 의무 완전 폐지.

- `완료` / `했어` → 오늘의 하나 완료 (P0에 이미 포함)
- `목요일까지야` → 마감 반영 (신규)
- 그 외 자유 문장 → 기존 v1 분류기로 흘려보냄 (신규 연결)

**DoD:** 한 주 동안 텔레그램에 **먼저 던진 적이 0회**여도 시스템이 굴러간다.

## P2 — 역할 재편

- 고정 4역할 폐기 → 사용자 정의 테이블
- **`몸`(재활·수면) 추가** ← v1에서 미분류로 떨어졌던 축
- 역할별 톤·기본 시각

**DoD:** `몸`이 실제로 브리핑에 등장한 날이 4주간 1일 이상.

## P3 ⭐ — 증명 레이어 연결 (게이트 직전 필수)

> **엔진만으로 4주를 버티는지 묻는 건 v1과 똑같은 실험이다.**
> 증명 장치를 붙인 상태로 측정해야 v2의 가설을 검증하는 것이 된다.

- 주간 리듬 리포트에 **역할별 무게 배분** 추가
- **"아침에 고른 하나를 끝낸 날 4/7"** 라인 추가 ← P0 데이터가 그대로 재료
- 글감 스튜디오 진입점을 리포트 안으로 통합 (독립 메뉴 폐지)

**DoD:** 매주 자동 발송 + 리포트에서 글감 스튜디오로 진입한 적 1회 이상.

## 배포 경로

P0 코드는 **독립 실행 가능한 Vercel 프로젝트**로 썼다. 두 가지 길이 있다.

**A. 기존 앱에 합치기 (권장)**
`imprint-os-app`에 `api/` `lib/` 를 복사하고 `vercel.json`의 `crons`를 병합. Supabase를 이미 쓰고 있으니 `schema.sql`만 추가로 실행.

**B. 별도 프로젝트로 먼저 띄우기**
기존 앱을 안 건드리고 P0만 검증하고 싶을 때. 같은 Supabase를 바라보게 하고, 텔레그램 webhook만 잠시 이쪽으로 돌린다.

> ⚠️ 봇 하나에 webhook은 하나만 걸린다. B로 갈 경우 기존 캡처가 끊기므로, `api/telegram.js`의 `captureFallback`에 v1 캡처 로직을 연결해두었다.
