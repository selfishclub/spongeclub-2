> **"내가 부르지 않아도, 역할이 바뀌는 순간에 먼저 와서 '지금 이거 하나'를 내민다.
> 그리고 매주, 그렇게 흘려보낸 것이 무엇이 됐는지 보여준다."**

- 작성일: 2026-07-28 / **버전: v2.1** (경쟁 분석 반영 개정)
- 선행 문서: [`00_기획점검.md`](./00_기획점검.md) — v1이 왜 안 쓰였는지

- v1: `imprint-os-app.vercel.app` (Next.js · Supabase · Claude Haiku · Telegram · Vercel)

### v2.0 → v2.1 개정 이유
v2.0은 글감 스튜디오를 **"부가 레이어"로 격하**했다. 이건 위계를 잘못 본 것이다.
**전환 비용 제거는 원리적으로 체감이 불가능한 가치**다(없어진 비용은 눈에 안 보인다). 따라서 그 효과를 **눈에 보이는 산출물로 환산해주는 장치**가 반드시 짝으로 필요하다. 글감 스튜디오와 주간 리듬 리포트가 정확히 그 장치다.
→ **부가 기능이 아니라 필수 부품.** v2.1은 이 구조 위에서 다시 쓴다.

## 0. 개편 요약

### 제품 구조 — 엔진과 증명

```
 [수집]  이미 남는 흔적 + 브리핑 답장          ← 새 입력을 요구하지 않는다
    ↓
 [엔진]  전환 브리핑 (매일)                    ← 가치를 만드는 곳 · 안 보인다
    ↓
 [증명]  주간 리듬 리포트 + 글감 스튜디오 (매주) ← 가치가 보이는 곳 · 이게 있어야 안 떠난다
```

**엔진 없이 증명만 있으면** → 재료가 없어 초안이 빈약해진다.
**증명 없이 엔진만 있으면** → **v1이 된다.** (실제로 그렇게 됐다)

### v1 → v2 대조

| | v1 | **v2** |
|---|---|---|
| **주도권** | 내가 던지고, 내가 부른다 (pull) | **시스템이 먼저 온다** (push) |
| **캡처** | 텔레그램에 한 줄 던지기 (의무) | **답장이 곧 캡처** (의무 폐지) |
| **복원** | "본업 복원"이라고 호출 | **전환 시점에 자동 도착** |
| **출력** | 열린 루프 5 + 글감 3 (목록=재료) | **"지금 이거 하나"** (완제품) |
| **누가 정하나** | — | **전날 밤 내가 승인.** AI가 정하지 않는다 |
| **개입 빈도** | 0 (내가 부를 때만) | **하루 2회, 전환 1개만** |
| **역할** | 고정 4개 | 사용자 정의, **`몸` 추가** |
| **주 무대** | 웹 대시보드 | **텔레그램** (웹은 동결) |
| **글감 스튜디오** | 나란한 신기능 | **증명 레이어** (엔진의 짝) |
| **성공 판정** | 배포했는가 | **4주 뒤에도 쓰고 있는가** |

## 1. 문제 정의

### 원래 문제 (유효함)
하루 안에서 **본업 · 콘텐츠 · 사이드 · 엄마 · 몸** 을 오간다. 일이 많아서 지치는 게 아니라, **역할을 넘어갈 때마다 머릿속을 재부팅**하는 데 에너지가 샌다.

> *어머니 재활치료 전화를 끊자마자 팀장 보고 자료를 여는 3분* — 매일 서너 번 발생한다.

### v1이 놓친 것 ①
맥락을 **잘 보관**했지만 **배달하지 못했다.** 보관은 창고고, 필요한 건 배달이다.

### v1이 놓친 것 ② — 더 근본적인 것
**전환 비용 제거는 체감할 수 없는 가치다.** 없어진 비용은 보이지 않고, "오늘 덜 피곤했다"는 반사실적 비교라 인간이 인지하지 못한다. 잘 작동해도 사용자는 모른다.

> 시장 증거: 전환 비용을 파는 회사(Clockwise·Reclaim.ai)는 **개인이 아니라 조직에 판다.** 개인에게 "집중 시간을 지켜드립니다"는 지불 의사로 바뀌지 않는다. 개인에게 팔리는 건 언제나 **환산된 결과물**이다.

### 그래서 v2가 푸는 문제
1. **"방금 역할이 바뀌었는데, 뭐부터 해야 하는지 다시 떠올리는 비용"** ← 엔진이 푼다
2. **"그게 줄었다는 걸 내가 느끼지 못하는 문제"** ← 증명이 푼다

**②를 안 풀면 ①을 아무리 잘 풀어도 떠난다.** v1이 그 증거다.

## 2. 페르소나

### 1차 사용자 (= 나, 첫 유저)
**장경아 / 웃는돌** — 직장인이면서 콘텐츠를 쓰고, 사이드 프로젝트를 굴리고, 엄마이고, 병가 복귀 후 몸 관리 중.
- 역할 5개 · 하루 전환 3~5회 · 기술 수준 상 · 텔레그램과 캘린더를 매일 씀

**결정적 제약:** *새 도구를 여는 습관을 만들 여력이 없다.* v1이 여기서 죽었으므로 1급 조건으로 못 박는다.

### 확장 사용자 (제품화 판단용 · **미검증 가설**)
역할이 3개 이상이고, 각 역할이 다른 맥락을 요구하며, 전환이 하루 3회 이상인 사람.
전형: n잡러 · 사이드 하는 직장인 · 워킹맘/대디 · 프리랜서.

> ⚠️ 나 자신에게서 4주 리텐션이 나오기 전엔 이들을 위해 **아무것도 만들지 않는다.**

## 3. 주요 가치 · 소구 방식 ⭐ (반드시 분리)

v2.0에선 이 둘을 한 칸에 썼다. **가장 중요한 개정이 여기다.**

### 주요 가치 (설계의 기준 — 내부용)
> **역할이 바뀌는 순간, 다시 떠올리지 않아도 된다.**

모든 기능은 이 기준으로 채택·기각한다. 바뀌지 않는다.

### 소구 방식 (사용자에게 파는 문장 — 외부용)
> ❌ ~~"역할 전환 비용을 줄여드립니다"~~ — **체감 불가. 팔리지 않는다.**
> ✅ **"흘려보낸 한 주가, 글 한 편이 됩니다."**

같은 제품을 **결과물의 언어**로 말한다. 온보딩·첫 화면·소개글은 전부 이쪽으로 쓴다.

**왜 이래야 하나 (상용 사례):** 성공한 "비용 절감형" 제품은 예외 없이 절감을 환산해 보여준다 — Clockwise `"이번 주 집중 시간 4.2시간 확보"`, RescueTime 주간 리포트, Superhuman `"Inbox Zero 5회"`. 환산 장치가 약한 Motion은 그 지점이 이탈 요인으로 지적된다. **v1엔 그게 아예 없었다.**

## 5. 핵심 기능 — 엔진

### 기능 1. 전환 브리핑 — 하루 2터치, 전환 1개 ⭐

> **v2.0에서 "하루 3~5회 · 전환 전부"로 잡았던 걸 철회한다.**
> Sunsama가 하루 1회 고강도 ritual로 자리잡은 반면, 저강도 다빈도 nudge 제품은 대부분 조용히 죽었다. 그리고 4주차에 배운 것 — **좁히는 결정이 곧 제품력.**

**대상 전환은 딱 하나.** 5개 역할 중 **가장 비싼 전환 1개**만 고른다.
- 초기 설정(가설): **`엄마 → 본업`** — 본인이 직접 *"그 3분의 거리"* 라고 쓴 그 전환
- ⚠️ 이건 기록 기반 추정이다. **P0 시작 전에 본인이 확정**한다.

**하루 2터치 — 성격이 정반대다**

| | 🌙 저녁 승인 (Sunsama형) | 🟢 아침 배달 (Readwise형) |
|---|---|---|
| 시각 | 21:30 (조정 가능) | 09:00 = 전환 시각 |
| 성격 | **의도적 ritual** — 응답을 요구함 | **순수 배달** — 응답 요구 0 (P9) |
| 하는 일 | 내일 그 하나를 **내가 고른다** | 어젯밤 고른 걸 **되돌려준다** |
| 안 하면 | 가장 오래 열린 것으로 자동 (표시함) | — |
| 버튼 | 숫자 하나 답장 | **버튼 없음** |

**🌙 저녁 (21:30)**
```
🌙 내일 아침 본업 시작할 때, 뭐 하나 할까요?

  1. 임원 보고 초안 마무리        (12일째 열림)
  2. 상품기획 파트 미팅 자료 정리   (5일째)
  3. 경쟁사 벤치마크 훑기         (2일째)

숫자 하나만 보내주세요. 다른 걸 쓰셔도 돼요.
그냥 두셔도 괜찮아요 — 1번으로 할게요.
```

**🟢 아침 (09:00)**
```
🟢 본업 모드예요.

▸ 지금 이거 하나
   임원 보고 초안 마무리

   어젯밤 직접 고르신 거예요.
```
- **버튼 없음. 읽기만 하면 가치가 완결된다** (P9). v2.0의 `[✅ 했어요][⏭ 오늘 말고][✍️ 다른 거]` 3버튼은 철회 — Readwise보다 훨씬 무거웠다.
- 자동 선택된 경우엔 **정직하게 표시**: *"가장 오래 열려 있어서 제가 골랐어요 (12일째)"* → 근거 없는 확신을 주지 않는 것이 신뢰의 조건 (P10).
- 후보가 없으면 **아무것도 보내지 않는다** (P7).

### 기능 2. 답장이 곧 캡처

별도 캡처 행위를 폐지한다.

| 내가 보내는 것 | 시스템이 하는 것 |
|---|---|
| `2` | 내일의 하나를 2번으로 확정 |
| `완료` | 오늘의 하나를 완료 처리 |
| `보고서 초안은 목요일까지야` | 마감 반영 |
| `막내 물리 과외 금요일 픽업` | 새 흔적으로 분류·저장 (= 기존 캡처) |

- 기존 자유 투척은 **살려두되 의무에서 해제**한다. 안 던져도 굴러가야 한다.
- **무응답에 벌점을 주는 UI를 만들지 않는다.** 스트릭·점수·연속 기록 전부 금지 — 이 제품은 이미 지친 사람을 위한 것이다.

### 기능 3. 역할은 내가 정의한다

- 온보딩에서 직접 만들고, 시기에 따라 추가·삭제·휴면
- 역할별 **기본 전환 시각**과 **톤** (본업=간결, 엄마=부드럽게, 몸=짧게)
- **웃는돌 초기값(5):** `본업` · `콘텐츠` · `사이드` · `엄마` · **`몸`**(재활·수면) ← v1에서 미분류로 떨어졌던 축을 승격
- **미분류는 무덤이 아니다.** 주간 리포트에서 반드시 마주치게 하고, 같은 주제가 3주 쌓이면 *"새 역할 만들까요?"*

### 기능 5. 글감 스튜디오 — 흔적이 무엇이 됐는지 보여주는 자리

**v1.2 기능 자체는 그대로 유지한다. 이번 개편에서 새로 만들지 않는다.** 바뀌는 건 **위상과 진입점**이다.

- **위상:** ~~부가 레이어~~ → **증명 레이어.** "흘려보낸 것이 이렇게 남았다"를 눈에 보이게 하는 유일한 장치
- **진입점:** 주간 리포트 안 + 콘텐츠 역할 브리핑 안. **독립 메뉴로 두지 않는다** (P4)
- **분리하지 않는 이유(중요):** 떼어내면 *백지에서 시작하는 평범한 AI 글쓰기 도구*가 되어 Sudowrite·Notion AI·Lex와 정면으로 붙게 된다. 이 기능의 유일한 해자는 **"내 흔적 corpus를 근거로 + 어떤 흔적이 쓰였는지 매핑"** 이고, 그 corpus는 엔진이 만든다. **떼면 해자가 같이 떨어진다.**

### 확장 패턴 (설계 메모) — 역할 하나당 깊이 레이어 하나

| 역할 | 깊이 레이어 | 상태 |
|---|---|---|
| 콘텐츠 | 글감 스튜디오 (흔적 → 글 초안) | ✅ v1.2 존재 |
| 본업 | **보고 포맷 변환** (인사이트 → 임원 슬라이드) | 🟡 1주차 스킬, **고아 상태** |
| 그 외 | — | 만들지 않음 |

> **1주차 스킬 처리:** `보고-포맷-변환`을 **'본업 역할의 증명 레이어' 백로그**로 정식 등록한다. 다만 **v2 범위에 넣지 않는다.** 지금 붙이면 v1의 실패(기능↑ 사용률↓)를 반복한다. 본캐가 4주 리텐션을 통과한 뒤에 꺼낸다.

## 7. 만들지 않을 것 ❌

- **범용 메모/노트 앱** — 노션·옵시디언과 싸우지 않는다
- **할일 관리의 완결성** — 프로젝트·하위작업·태그·반복 없음. **전환 순간에 필요한 만큼만** 안다
- **캘린더 대체** — 읽기만 한다
- **웹 대시보드 확장** — 주 1회 보는 창. 타임라인·필터·편집 고도화 **전부 동결**
- **위치·화면·앱 사용 추적** — 프라이버시 비용 > 이득. 전환은 시간 규칙·캘린더·한 마디로만
- **게이미피케이션(스트릭·점수·연속 기록)** — 지친 사람에게 죄책감을 주는 장치 금지
- **AI 자동 우선순위 (P0~P2 동안)** — 신뢰가 쌓인 뒤에
- **버튼·인터랙션이 많은 브리핑** — 읽고 끝나야 한다
- **팀·공유·협업** / **여러 유저용 범용 서비스** — v2 범위 밖

## 8. 성공 기준

> v1의 실패는 "배포 못 함"이 아니라 **"안 쓰게 됨"** 이었다. 지표를 전부 리텐션으로 바꾼다.

### 필수 (하나라도 못 넘기면 v2도 실패)
| 지표 | 기준 | 왜 |
|---|---|---|
| **4주 연속 사용** | 4주차에도 브리핑이 살아 있다 | **v1이 정확히 여기서 죽었다.** 단일 최중요 지표 |
| **저녁 승인률** | 주 4일 이상 숫자 답장 | 유일하게 응답을 요구하는 지점 |
| **아침 브리핑 완료율** | 고른 하나를 끝낸 날 주 3일 이상 | 엔진이 실제로 작동하는지 |
| **무시율** | 30% 이하 | 넘으면 즉시 빈도 하향 (P7) |

### 증명 지표 🆕 (P8 — 이게 안 되면 또 떠난다)
- 주간 리포트를 **끝까지 읽는다** (열람 후 30초 이상 / 글감 링크 클릭)
- **4주 안에 실제 글 1편 발행** — 흔적 → IP 전환이 한 번이라도 눈으로 확인돼야 한다
- *"이거 없었으면 그냥 흘러갔을 텐데"* 라는 말이 나온다

### 균형
- **`몸` 역할이 4주간 0이 아니다** — 시스템이 내 삶의 축을 붙잡고 있는지의 리트머스

### 제품화 게이트 (도달 전 확장 착수 금지)
필수 4개 + 증명 지표 통과 → 확장군 인터뷰 5명 → 나 외 **3명이 2주 이상** 사용

## 10. 데이터 · 프라이버시

**문제:** 아이 일정·건강 기록이 `텔레그램 → Vercel → Anthropic → Supabase` 를 통과한다. v2는 **더 많은** 개인 맥락을 다루므로 전제 조건이다.

**원칙**
1. **최소 전송** — 분류에 필요한 건 역할 라벨뿐. 전체 문장을 매번 보낼 필요 없음
2. **민감 역할 격리** — `엄마` · `몸` 은 외부 모델 호출 없이 **규칙 기반만**으로 처리 가능하게
3. **보존 기한** — 원문은 N일 뒤 요약만 남기고 폐기
4. **삭제권** — 역할 단위 일괄 삭제
5. 확장 시: 사용자 간 데이터 격리 · 처리 고지

> 🔴 **미결정 2건 (P3 착수 전 결정):** ① 격리 수준(완전 로컬 vs 민감 역할만 분리) ② 원문 보존 기한 기본값
> 참고: 개인 맥락 제품(Rewind·Limitless 계열)의 확장 병목은 기능이 아니라 **신뢰**였다.

## 11. 로드맵

> **본캐 하나가 4주 리텐션을 통과할 때까지 아무것도 추가하지 않는다.**

| Phase | 무엇 | 완료 기준 |
|---|---|---|
| **P0** ⭐ | **전환 1개 · 하루 2터치.** 저녁 승인 + 아침 배달. AI 판단 없음, 버튼 없음 | 7일 연속 도착 + 저녁 승인 4일 이상 |
| **P1** | **답장 = 캡처.** `완료`·자연어 답장으로 완료·마감·신규 반영 | 별도 캡처 없이 일주일 굴러감 |
| **P2** | **역할 재편.** 사용자 정의 + `몸` 추가 + 역할별 톤/시각 | `몸`이 실제 브리핑에 등장 |
| **P3** ⭐ | **증명 레이어 연결.** 주간 리듬 리포트에 무게 배분 + 글감 스튜디오 진입점 통합 | 매주 자동 발송 + 글감 진입 |
| **— 게이트 —** | **4주 리텐션 측정.** 통과 못 하면 이후 전부 보류하고 원인 규명 | §8 필수 4개 + 증명 지표 |
| **P4** | 캘린더 신호 트리거 + 프라이버시 구조 확정 | 오작동 없이 동작 |
| **P5** | 전환 대상 2~3개로 확대 (무시율 30% 이하 유지 조건) | 빈도 늘려도 무시율 유지 |
| **P6** | 확장군 인터뷰 5명 → 3명 투입 | 나 외 3명 2주 사용 |
| **백로그** | 본업 증명 레이어 (`보고-포맷-변환` 회수) | P6 이후 판단 |

**⚠️ P3(증명)를 게이트 앞에 둔 이유:** 엔진만으로 4주를 버티는지 묻는 건 **v1과 똑같은 실험**이다. 증명 장치를 붙인 상태로 측정해야 v2의 가설을 검증하는 것이 된다.

## 12. 열린 질문 (5주차 과제 1 "구현, 그 다음의 것"과 직결)

1. **가장 비싼 전환은 정말 `엄마 → 본업`인가?** 기록 기반 추정이다. P0 시작 전 확정 필요.
2. **개입 빈도의 상한은?** 하루 2회로 시작한다. 무시율 30%를 넘지 않으면서 몇 개의 전환까지 늘릴 수 있는가 — P0/P5 실측으로 답한다.
3. **자동 선택이 틀렸을 때 신뢰는 몇 번 만에 무너지는가?** P10을 언제 풀 수 있는가. 확신 없을 땐 **추천하지 않고 넘어가는 편**이 나은가?
4. **가장 사적인 데이터를 다루는 제품을 남에게 열 수 있는가?** 확장의 진짜 병목은 여기일 수 있다.
5. **소구 문장("한 주가 글 한 편이 됩니다")이 나 아닌 사람에게도 통하는가?** 콘텐츠를 안 쓰는 n잡러에겐 무엇으로 환산해야 하는가.
