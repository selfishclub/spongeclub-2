> **"내가 부르지 않아도, 역할이 바뀌는 순간에 먼저 와서 '지금 이거 하나'를 내민다."**

- 작성일: 2026-07-28 / 버전: v2.0 (전면 개편)
- 선행 문서: [`00_기획점검.md`](./00_기획점검.md) — v1이 왜 안 쓰였는지

## 0. 개편 요약 — 무엇이 바뀌는가

| | v1 | **v2** |
|---|---|---|
| **주도권** | 내가 던지고, 내가 부른다 (pull) | **시스템이 먼저 온다** (push) |
| **캡처** | 텔레그램에 한 줄 던지기 (새 입력 요구) | **브리핑에 답장하면 그게 캡처** (요구 없음) |
| **복원** | "본업 복원"이라고 호출 | **전환 시점에 자동 발송** |
| **출력** | 열린 루프 5 + 글감 3 (목록=재료) | **"지금 이거 하나" + 이유 한 줄** (완제품) |
| **역할** | 고정 4개 (본업/콘텐츠/사이드/엄마) | **사용자 정의 + 시기별 변경**, 초기값에 **몸** 추가 |
| **주 무대** | 웹 대시보드 | **텔레그램** (웹은 주 1회 보는 창으로 강등) |
| **핵심 가치** | 캡처·분류·복원 + 회고 + 자산화 (3축 병렬) | **역할 전환 비용 제거 하나** (자산화는 하위 레이어) |
| **성공 판정** | 배포됐는가 | **4주 뒤에도 쓰고 있는가** |

**한 줄 요약:** *기록 시스템을 그만두고, **전환 순간 개입 시스템**이 된다.*

## 1. 문제 정의

### 원래 문제 (유효함 — 이건 안 바뀐다)
하루 안에서 **본업 · 콘텐츠 · 사이드 · 엄마 · 몸** 이라는 역할을 오간다. 일이 많아서 지치는 게 아니라, **역할을 넘어갈 때마다 머릿속을 재부팅**하는 데 에너지가 샌다.

> *어머니 재활치료 전화를 끊자마자 팀장 보고 자료를 여는 3분* — 그 3분이 매일 서너 번 발생한다.

### v1이 풀지 못한 진짜 문제
전환 비용을 없애려면 **전환하는 그 순간에** 맥락이 도착해야 한다. v1은 맥락을 **잘 보관**했지만, 도착시키지 못했다. 보관은 창고고, 필요한 건 배달이다.

### 그래서 v2가 푸는 문제
> **"방금 역할이 바뀌었는데, 뭐부터 해야 하는지 다시 떠올리는 데 드는 시간과 에너지"**

이것 하나만 푼다.

### 지금까지의 대체재
- 머리로 기억한다 (→ 새고, 피곤하다)
- 캘린더를 다시 열어 훑는다 (→ 일정은 있지만 '맥락'은 없다)
- 메모 앱을 뒤진다 (→ 어디에 적었는지부터 찾아야 한다)
- **v1 흔적 OS** (→ 내가 불러야 해서 안 부르게 됐다)

## 2. 페르소나

### 1차 사용자 (= 나, 첫 유저)
**장경아 / 웃는돌** — 직장인이면서 콘텐츠를 쓰고, 사이드 프로젝트를 굴리고, 엄마이고, 병가 복귀 후 몸 관리 중.
- 역할 수: 5개
- 하루 전환 횟수: 3~5회
- 기술 수준: 상 (직접 만들고 배포함)
- 이미 텔레그램·캘린더를 매일 쓴다

**결정적 특성:** *새 도구를 여는 습관을 만들 여력이 없다.* v1이 실패한 이유가 이것이므로, 이 제약을 페르소나의 1급 조건으로 못 박는다.

### 확장 사용자 (제품화 판단용 · 아직 미검증)
같은 구조를 가진 사람 — **역할이 3개 이상이고, 각 역할이 서로 다른 맥락을 요구하며, 전환 빈도가 하루 3회 이상인 사람.**
전형: n잡러 · 사이드 프로젝트 하는 직장인 · 워킹맘/대디 · 프리랜서(클라이언트별 전환).

> ⚠️ 확장군은 **가설이다.** 나 자신에게서 4주 리텐션이 나온 뒤에 인터뷰로 검증한다. 그 전엔 이들을 위해 아무것도 만들지 않는다.

## 3. 주요 가치 · 소구 방식 ⭐

**주요 가치:** 역할이 바뀌는 순간, 다시 떠올리지 않아도 된다.

**소구 방식(한 문장):**
> *"엄마에서 팀장으로 넘어가는 그 3분에, 시스템이 먼저 와서 '지금은 이거 하나'라고 말해준다."*

**이게 되면 무엇이 달라지나**
- 전환할 때마다 켜지던 머리를 안 켜도 된다
- 병렬 운영이 '애쓰는 일'에서 '따라오는 결과'가 된다
- 하루가 증발하지 않고 남는다 *(→ 주간 리듬 리포트가 매주 증명한다)*

| **P2** | **완제품을 준다.** 목록이 아니라 "지금 이거 하나" | 목록을 보고 우선순위 정하는 건 또 다른 재부팅이었다 |

| **P7** | **조용함이 기능이다.** 개입 총량에 상한을 둔다 | (신규) push 제품의 유일한 죽음 원인은 알림 피로다 |

## 5. 핵심 기능 — 본캐 (역할 전환 비용 제거)

> 아래 4개가 전부다. 이것 말고는 v2에 없다.

### 기능 1. 전환 브리핑 (Push) — 제품의 심장

역할이 바뀌는 시점에 **텔레그램으로 먼저 도착한다.**

**트리거 (자동 감지를 과신하지 않는다 — 신뢰도 순으로 3단계)**
1. **시간 규칙** — 사용자가 정한 고정 전환 시각 (예: `09:00 본업` / `19:30 엄마` / `22:00 콘텐츠`). 가장 단순하고 가장 확실하다. **P0는 이것만으로 시작한다.**
2. **캘린더 신호** — 일정 시작 10분 전 / 종료 직후. 일정 제목에서 역할을 추정.
3. **한 마디 선언** — 텔레그램에 `엄마` 라고만 보내면 즉시 그 역할 브리핑.

**출력 형식 (완제품 — P2)**
```
🟡 콘텐츠 모드로 넘어갈 시간이에요

▸ 지금 이거 하나
   브런치 초안 "엄마에서 팀장으로" 오프닝 문단 끝내기
   왜 → 6일째 열려 있고, 이번 주 유일한 발행 예정 건

▸ 참고로 하나만    (선택 · 접힘)
   링크드인 글감 3개 대기 중

[ ✅ 했어요 ]  [ ⏭ 오늘 말고 ]  [ ✍️ 다른 거 할래요 ]
```

- **"지금 이거 하나"는 항상 1개.** 2개 이상 보여주면 선택 비용이 생기고, 그게 재부팅이다. *(4주차 고고버디에서 유저 검증된 패턴을 역수입)*
- **왜 그것인지 한 줄**을 반드시 붙인다. 근거 없는 추천은 신뢰가 안 쌓인다 — v1이 "쌓였는데 쓸만하지 않았던" 이유.
- 나머지는 **접어둔다.** 펼치는 건 사용자 선택.

### 기능 2. 답장이 곧 캡처 (Capture 없는 캡처)

**별도의 캡처 행위를 폐지한다.** 브리핑에 답장하는 것만으로 시스템이 갱신된다.

| 내가 보내는 것 | 시스템이 하는 것 |
|---|---|
| `✅ 했어요` | 해당 루프 완료 처리 |
| `⏭ 오늘 말고` | 다음 등장 시점 미룸 + 미룬 횟수 누적 |
| `보고서 초안은 목요일까지야` | 마감 반영 + 우선순위 재계산 |
| `막내 물리 과외 금요일 픽업` | 새 흔적으로 분류·저장 (= 기존 캡처) |

- 기존 텔레그램 자유 투척은 **그대로 살려둔다.** 유일하게 끝까지 작동했던 통로이고, 죽이는 게 아니라 **의무에서 해제**하는 것이다. 안 던져도 시스템이 굴러가야 한다.
- 브리핑에 답을 안 해도 정상 동작한다. **무응답에 벌점을 주는 UI를 만들지 않는다.**

### 기능 3. 역할은 내가 정의한다

- 온보딩에서 역할을 직접 만든다. **시기에 따라 추가·삭제·휴면** 가능 (예: 입시기엔 '입시', 병가기엔 '몸' 비중 상향).
- 각 역할마다 **기본 전환 시각**과 **브리핑 톤**을 따로 둔다. (본업=간결/명령형, 엄마=부드럽게, 몸=짧게)
- **웃는돌 v2 초기값 (5개):** `본업` · `콘텐츠` · `사이드` · `엄마` · **`몸`**(재활·수면)
  → v1에서 미분류로 떨어졌던 축을 정식 역할로 승격.
- **미분류는 무덤이 아니다.** 주간 리포트에서 반드시 한 번 마주치게 하고, 3주 연속 미분류에 같은 주제가 쌓이면 **"새 역할 만들까요?"** 를 제안한다.

### 기능 4. 주간 리듬 리포트 (살아남은 것을 강화)

v1.1의 주간 회고가 유일하게 계속 살아 있었다. 여기에 **본캐의 증거**를 얹는다.

```
📊 이번 주, 당신은 여기에 살았어요

  본업    ████████████░░░░  62%
  엄마    ████░░░░░░░░░░░░  21%
  콘텐츠  ██░░░░░░░░░░░░░░  11%
  사이드  █░░░░░░░░░░░░░░░   4%
  몸      ░░░░░░░░░░░░░░░░   2%  ← 3주 연속 최하위

▸ 가장 오래 열려 있는 루프: "PoC 인터뷰 질문지" (17일)
▸ 이번 주 넘어간 전환: 21회 · 브리핑 응답 15회
▸ 글로 발전시킬 만한 글감: 2개  → [초안 만들기]
```

- **역할별 무게 배분**이 새로 들어간다. "하루가 증발하지 않았다"를 **숫자로** 보여주는 자리.
- 글감 스튜디오 진입점은 **여기 안에만** 둔다. 따로 열러 갈 일을 만들지 않는다 (P4).

## 6. 부가 레이어 — 자산화 (본캐 아님, 격하)

**글감 스튜디오** (v1.2) — 흔적을 채널별 글 초안으로. **유지하되 위상을 명확히 한다.**

> 이건 **'콘텐츠'라는 하나의 역할에 깊이를 더하는 레이어**이지, 흔적 OS의 본캐가 아니다.

- 진입점: 주간 리포트 안 + 콘텐츠 역할 브리핑 안. **독립 메뉴로 두지 않는다.**
- 기능 자체는 v1.2 그대로 (근거 매핑 포함). 이번 개편에서 **새로 만들지 않는다.**

**확장 패턴 (설계 메모):** 이 구조는 일반화된다 — *역할 하나당 깊이 레이어 하나.*

| 역할 | 깊이 레이어 | 상태 |
|---|---|---|
| 콘텐츠 | 글감 스튜디오 (흔적 → 글 초안) | ✅ v1.2 존재 |
| 본업 | **보고 포맷 변환** (인사이트 → 임원 슬라이드) | 🟡 1주차 스킬로 존재, **고아 상태** |
| 그 외 | — | 만들지 않음 |

> **1주차 스킬 처리 결정:** `보고-포맷-변환`은 폐기하지 않고 **'본업 역할의 깊이 레이어' 백로그**로 정식 등록한다. 다만 **v2 범위에 넣지 않는다.** 1주차 인터뷰가 지목한 "가장 소진되는 지점"이었으므로 버리기엔 아깝지만, 지금 붙이면 v1의 실패(기능 수↑ 사용률↓)를 그대로 반복한다. **본캐가 4주 리텐션을 통과한 뒤에** 꺼낸다.

## 7. 만들지 않을 것 ❌

*(4주차에 배운 것 — "무엇을 안 만들까가 더 어렵고 중요하다")*

- **범용 메모/노트 앱** ❌ — 노션·옵시디언과 싸우지 않는다
- **할일 관리의 완결성** ❌ — 프로젝트·하위작업·태그·반복 규칙 없음. **전환 순간에 필요한 만큼만** 안다
- **캘린더 대체** ❌ — 캘린더는 읽기만 한다. 일정을 여기서 만들지 않는다
- **웹 대시보드 기능 확장** ❌ — 웹은 주 1회 보는 창. 타임라인·필터·편집 고도화 전부 동결
- **자동 역할 감지를 위한 위치·화면·앱 사용 추적** ❌ — 프라이버시 비용이 이득보다 크다. 전환은 **시간 규칙 + 캘린더 + 한 마디**로만 잡는다
- **게이미피케이션(스트릭·점수·연속 기록)** ❌ — 안 쓴 날에 죄책감을 주는 장치는 만들지 않는다. 이 제품은 이미 지친 사람을 위한 것이다
- **팀·공유·협업** ❌
- **여러 유저용 범용 서비스** ❌ (v2 범위 밖. 나에게서 4주 리텐션 나온 뒤 판단)

## 8. 성공 기준 — 행동으로

> v1의 실제 실패는 "배포 못 함"이 아니라 **"안 쓰게 됨"** 이었다. 그러므로 지표를 전부 **리텐션**으로 바꾼다.

### 필수 (하나라도 못 넘기면 v2도 실패다)
| 지표 | 기준 | 왜 이 숫자 |
|---|---|---|
| **4주 연속 사용** | 4주차에도 브리핑에 반응 | **v1이 정확히 여기서 죽었다.** 단일 최중요 지표 |
| **주간 응답률** | 주 5일 이상, 브리핑에 반응(버튼·답장) | '여는 것'이 아니라 '반응하는 것'을 센다 |
| **무시율** | 30% 이하 | 넘으면 알림 피로 — 즉시 빈도 하향 |

### 질적 (말로 확인)
- *"역할 바꿀 때 머리 다시 켜는 느낌이 줄었다"* 는 말이 실제로 나온다
- *"이건 안 열어도 알아서 온다"* 는 감각이 생긴다

### 균형
- **`몸` 역할이 4주간 0이 아니다** — 시스템이 내 삶의 축을 실제로 붙잡고 있는지의 리트머스

### 제품화 게이트 (여기 도달 전엔 확장 착수 금지)
- 위 필수 3개 통과 → **그 다음에** 확장군 인터뷰 5명 → 나 외 **3명이 2주 이상** 사용

## 9. 차별화

| 갈래 | 대표 | 한계 | 흔적 OS v2 |
|---|---|---|---|
| 메모·캡처 | 노션 · 옵시디언 · Apple 메모 | 넣기는 쉬운데 **꺼내는 건 전부 내 몫** | 안 꺼내도 **알아서 온다** |
| 읽기 리마인드 | Readwise | 되살려주지만 **콘텐츠 소비 영역만** | 삶의 **역할 맥락**을 되살림 |
| 하루 계획 | Sunsama · Motion | 하루를 **한 번** 설계 | 하루 **안에서 3~5번** 개입 |
| 할일 관리 | Things 3 · Todoist | 목록을 주고 **우선순위는 내가** | **"지금 이거 하나"** 만 준다 |
| AI 비서 | 각종 AI 어시스턴트 | 물어봐야 답함 (pull) | **안 물어봐도 옴** (push) |
| **v1 흔적 OS** | — | 보관은 훌륭, **배달이 없음** | **배달이 제품 전체** |

**한 문장:**
> *Readwise의 "되살려줌"을 콘텐츠가 아니라 **삶의 역할**에, Things의 "지금 하나"를 **전환의 순간**에 붙인 것. 그리고 아무것도 묻지 않아도 먼저 온다.*

## 10. 데이터 · 프라이버시 (3주차 미해결 숙제 정면 처리)

**문제:** 아이 일정·건강 기록 같은 가장 사적인 데이터가 `텔레그램 → Vercel → Anthropic → Supabase` 를 통과한다.
**v2에선 이게 전제 조건이다.** push 제품은 v1보다 **더 많은** 개인 맥락을 다루기 때문이다.

**원칙**
1. **최소 전송** — 분류에 필요한 건 역할 라벨뿐이다. 전체 문장을 매번 보낼 필요가 없다
2. **민감 역할 격리** — `엄마` · `몸` 은 **로컬/자체 저장 전용 모드** 선택 가능. 이 역할은 외부 모델 호출 없이 규칙 기반으로만 처리
3. **보존 기한** — 원문은 N일 뒤 요약만 남기고 폐기 (기본값 결정 필요)
4. **삭제권** — 역할 단위 일괄 삭제
5. 확장 시 필수: 사용자 간 데이터 격리 · 데이터 처리 고지

> 🔴 **미결정:** 위 2번(로컬 격리)을 어느 수준까지 갈 것인가 — 완전 로컬 앱으로 갈지, 서버는 두되 민감 역할만 분리할지. **P3 착수 전에 결정한다.**

| Phase | 무엇 | 완료 기준 |

| **P1** | **답장 = 캡처.** 버튼·자연어 답장으로 완료·미룸·신규 반영 | 별도 캡처 없이 일주일 굴러간다 |
| **P2** | **역할 재편.** 사용자 정의 + `몸` 추가 + 역할별 톤/시각 | 몸 역할이 실제로 브리핑에 등장한다 |
| **— 게이트 —** | **4주 리텐션 측정.** 통과 못 하면 P3 이후 전부 보류하고 원인 규명 | §8 필수 3지표 |

| **P4** | 주간 리듬 리포트 강화 (역할별 무게 배분) | 매주 자동 발송 |

| **백로그** | 본업 깊이 레이어(`보고-포맷-변환` 회수) | P5 이후 판단 |

## 12. 열린 질문 (5주차 과제 1 "구현, 그 다음의 것"과 직결)

1. **개입 빈도의 상한은 몇 번인가?** 하루 3회는 도움이고 8회는 소음이다. 그 경계를 어떻게 찾을 것인가 — 처음부터 낮게 잡고 올릴 것인가, 반대인가.
2. **"지금 이거 하나"의 추천이 틀렸을 때 신뢰는 몇 번 만에 무너지는가?** 틀린 추천 3번이면 브리핑을 안 읽게 될 것 같다. 그렇다면 **확신 없을 땐 추천하지 않고 넘어가는 편**이 나은가?
3. **가장 사적인 데이터를 다루는 제품을 남에게 여는 게 가능한가?** 아이 일정과 건강 기록을 맡기라고 말하려면 무엇이 갖춰져야 하는가. 이게 확장의 진짜 병목일 수 있다.
4. **자동 전환 감지에 얼마나 투자할 가치가 있는가?** 시간 규칙만으로 80%가 잡히면, 나머지 20%를 위해 캘린더·추적을 붙이는 건 손해일 수 있다. — **P0의 실측으로 답한다.**
